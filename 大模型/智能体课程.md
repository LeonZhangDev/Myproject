



# 智能体介绍

   如果说 RetrievalQA 链是一个遵循固定流程的“自动化流水线”，那么 Agent 就是一个拥有**自主决策能力**的“智能机器人”。它是当前大语言模型（LLM）应用中最前沿、最强大的范式之一。

**一  核心概念：它是什么？**

​      **Agent 的核心思想是使用一个大语言模型（LLM）作为其“大脑”或“决策核心”，来理解用户需求、制定计划、选择工具（Tools）、执行动作（Actions）、并观察结果，最终完成一个复杂的任务。**

简单来说，一个 Agent 的运作模式是：
**思考（Think） -> 行动（Act） -> 观察（Observe） -> ... -> 最终完成**

这非常类似于人类的思考方式。比如，当被问到“奥利奥卡路里高吗？”时，一个 Agent 可能会这样工作：

1. **思考**：“用户问的是奥利奥的卡路里。我自己没有实时数据，但我可以调用网络搜索工具。”
2. **行动**：调用 `google_search` 工具，输入查询关键词 “Oreo calorie content”。
3. **观察**：工具返回了搜索结果，例如 “一份（3块）奥利奥含有约 160 卡路里”。
4. **再思考**：“我得到了数据。现在需要判断这个数值是否算‘高’。我可以调用一个计算工具，将其与常见零食对比，或者直接用我的知识进行推理。”
5. **再行动/回答**：基于推理，生成最终答案：“一份（3块）奥利奥大约含有160卡路里。相比于一些水果（如一个苹果约95卡），这个热量相对较高，属于能量密度较高的零食，应适量食用。”

 **二 为什么需要 Agents？解决了什么问题？**

尽管LLM本身非常强大，但它有固有的局限性：

1. **知识滞后与幻觉**：如前所述，LLM的知识有截止日期，且会编造信息。
2. **无法执行外部动作**：LLM可以写代码，但不能真正运行代码；它可以描述如何发送邮件，但不能真的帮你发邮件。
3. **数学计算、实时信息获取等能力弱**：LLM可能不擅长精确计算或获取最新信息。

**Agents 通过“工具使用（Tool Use）”能力，将 LLM 的推理和语言能力与外部工具的强大功能结合起来，突破了LLM自身的限制，使其成为一个真正的“数字助手”。**

**三、核心组成部分**

一个典型的 Agent 由以下几个关键部分构成：

1. **LLM (大脑)**
   - 负责所有的推理和决策。它决定下一步该做什么，使用哪个工具，以及如何解释工具返回的结果。
2. **工具 (Tools)**
   - Agent 可以调用的外部函数。这是 Agent 能力的扩展。
     - **自定义工具**： 你可以定义任何工具，如：查询数据库、发送邮件、操作浏览器、控制智能家居等。
3. **代理（Agent）本身**
   - 这是逻辑部分，它封装了 LLM 如何做决策的策略。不同的 Agent 类型有不同的决策逻辑（见下文）。
4. **代理执行器 (Agent Executor)**
   - 这是运行 Agent 的“引擎”。它负责调用 Agent 做决策，然后执行它选择的工具，将结果返回给 Agent 进行下一步思考，并循环这个过程。它还负责处理错误、管理循环以防无限循环等。



**四 智能体与 RAG 的关系**

> **RAG 是 Agent 的“知识插件”。**

在智能体体系中：

- 智能体是“大脑”；
- 工具是“手脚”；
- RAG 是“记忆或外部知识库”

举个例子👇：

```
用户：请告诉我《劳动法》中关于加班工资的规定。

```

- 🔍 **RAG**：从法律知识库中检索出相关条款；
- 🧠 **Agent**：读取检索结果，理解用户意图；
- 🗣️ **LLM生成回答**：综合检索结果后输出完整解释。

**总结一句话：**

智能体决定“何时需要RAG”，RAG只是它用来增强回答的一种工具。

## 2 基于 Agent 和 工具的基础

### 2.1. **Agent 的工作原理**

**Agent** 是一个能够根据给定的输入生成任务，并且调用不同工具来处理这些任务的智能系统。在 **LangChain** 中，Agent 是一个可以根据用户的需求，通过与多个工具的交互来完成复杂任务的组件。

**Agent 工作原理：**

- **理解任务**：根据输入，Agent 会解析用户的需求并识别所需执行的任务。
- **选择工具**：根据任务类型，Agent 会选择适当的工具来执行操作。
- **工具调用与执行**：调用选定的工具，并传递适当的参数。
- **结果反馈**：执行完成后，Agent 会返回处理结果或执行下一步操作。

### 2.2 **创建与使用 Tools**

在 LangChain 中，Tools 是 Agent 执行任务的“助手”。每个 Tool 是一个独立的功能模块，它能够处理不同类型的任务。

**创建工具（Tools）**

每个 Tool 都是一个可以被 Agent 调用的函数或 API。你可以创建自定义工具或使用现成的工具库。

**示例：创建一个发送邮件的 Tool**

```python
import smtplib
from email.mime.text import MIMEText
from dotenv import load_dotenv
import os
from langchain.tools import tool
from pydantic import BaseModel, Field
# 1. 标准化参数）
class SendEmailArgs(BaseModel):
    title: str = Field(description="邮件标题")
    content: str = Field(description="邮件正文")
    to_email: str = Field(description="收件人邮箱")
# 使用 @tool 装饰器来创建邮件发送工具
@tool(args_schema=SendEmailArgs)
def send_email(title: str, content: str, to_email: str) -> str:
    """
      发送邮件
     """
    load_dotenv()  # 加载环境变量
    msg = MIMEText(content )
    msg['Subject'] = title
    msg['From'] = os.getenv("email_user")
    msg['To'] = to_email

    try:
        with smtplib.SMTP_SSL(os.getenv("email_host"), 465) as s:
            s.login(os.getenv("email_user"), os.getenv("email_password"))
            s.sendmail(os.getenv("email_user"), to_email, msg.as_string())
        return "发送成功"
    except Exception as e:
        print("有异常",e)
        return f"邮件已成功发送到 {to_email}"

```



**使用工具**

你可以通过创建一个 **AgentExecutor** 来结合多个工具并执行任务。

```python
from langchain.agents import  AgentExecutor
from langchain_core.prompts import MessagesPlaceholder, ChatPromptTemplate

from tool.send_email_tool import  send_email
from model.my_chat_model import ChatModel
from langchain.agents import create_tool_calling_agent

def one():
    #1 创建大模型
    model = ChatModel()
    llm = model.get_line_model()
    #2 创建提示模板
    prompt = ChatPromptTemplate.from_messages([
        ("system", "你是一个AI助手."),
        ("user", "{input}"),
        MessagesPlaceholder(variable_name="agent_scratchpad"),
    ])
    # 3 定义工具
    tools = [send_email]
    # 4 创建智能体
    agent = create_tool_calling_agent(
        llm,
        tools,
        prompt
    )
    # 5 创建代理执行器
    agent_executor = AgentExecutor(agent=agent, tools=tools, verbose=True)
    #提示
    print("邮件发送Agent智能体启动")
    # 6运行
    rs =agent_executor.invoke({"input":"帮我发邮件给767920412@qq.com，主题是'会议通知'，内容是'本周五下午3点有重要会议，请准时参加"})
    print(rs)
if __name__ == '__main__':
    one()

```

**关键代码解释**

**1 ChatPromptTemplate**：这是一个用于构建提示的模板对象，它将系统信息和用户输入结合在一起，用于与模型进行交互。

`from_messages`：通过 `from_messages` 方法，你创建了一个模板，它包括以下三条消息：

1. 系统消息（`system`）：初始化对话上下文，告诉模型它是一个 AI 助手。
2. 用户消息（`user`）：这里的 `{input}` 是占位符，将动态填充为用户提供的实际输入（如 "帮我发邮件"）。
3. `MessagesPlaceholder`：这是一个占位符，用于存储“代理草稿”（`agent_scratchpad`）。在此上下文中，它可能是用于中间步骤的信息

**2 create_tool_calling_agent**`：这是 LangChain 提供的一个函数，用来创建一个 Agent，该 Agent 将结合指定的大模型（`llm`）和工具（`tools`），并通过给定的提示模板（`prompt`）进行工作。

- `llm`：这里传入的语言模型实例。
- `tools`：工具列表，在这里就是 `send_email` 工具。
- `prompt`：聊天模型的输入模板，用于定义与模型交互的方式。

`create_tool_calling_agent` 创建的 Agent 将具备在执行过程中根据提示调用工具的能力，是最新的langchain创建工具，代替了  旧版的 **initialize_agent**



**3 AgentExecuto**r：这是 LangChain 提供的用于执行 Agent 的类。它会将 **Agent** 和 **工具列表** 结合起来，确保任务能够被执行。

`verbose=True`：启用详细日志输出，可以帮助调试过程中的问题，显示 Agent 执行任务时的详细信息。

**4 invoke**`：这个方法调用 Agent 来执行任务，参数是一个包含用户请求的字典。在这里，字典的键是 `input`，值是用户请求的邮件任务

**2  对接数据源**

接入外部数据源是自定义 Agent 的一个重要部分。无论是数据库、外部 API 还是文件，Agent 都需要能够访问这些数据源以完成任务。以数据库查询为例，我们的 `sql_tool` 工具就是通过 MySQL 连接来访问数据库。



在上面的例子中，我们假设数据库中有一个名为 `employees` 的表，包含员工的相关信息（如 `name`、`department`、email等）。Agent 可以使用这个工具查询特定的员工信息。

**3 prompt的设计**

**设计目标**

​     我们希望通过设计一个 **基于 Prompt 的 Agent**，使得 Agent 能够根据用户的请求分解任务，并且在必要时调用外部工具（如数据库查询、邮件发送、API 调用等）。通过精心设计的 Prompt，我们能够让 Agent 更加智能地理解复杂任务，并进行合理的分解与执行



```python
from langchain_core.prompts import MessagesPlaceholder, ChatPromptTemplate
from langchain.agents import AgentExecutor,create_tool_calling_agent

from tool.sql_tool import sql_tool
from model.my_chat_model import ChatModel

def one():
    # 1 创建大模型
    model = ChatModel()
    llm = model.get_line_model()
    # 创建提示模板
    prompt = ChatPromptTemplate.from_messages([
        ("system", "你是一个数据库助手，能够回答有关公司员工的问题。数据库表格结构： employer 员工表，返回的数据必须是json格式"),
        ("user", "{input}"),
        MessagesPlaceholder(variable_name="agent_scratchpad"),
    ])

    # 创建自定义 Agent
    tools = [sql_tool]
    agent = create_tool_calling_agent(
        llm,
        tools,
        prompt
    )

    # 创建代理执行器
    agent_executor = AgentExecutor(agent=agent, tools=tools, verbose=True)

    # 用户输入：查询员工信息
    user_input = "请告诉我行政部部门的所有员工信息。"

    # 执行查询
    response = agent_executor.invoke({"input": user_input})
    print(response["output"])
if __name__ == '__main__':
    one()

```

```
        ("system", "你是一个数据库助手，能够回答有关公司员工的问题。数据库表格结构： employer 员工表，返回的数据必须是json格式"),
```

- **提示词里一定要说明 “数据库表格结构： employer 员工表”，让大模型根据你的问题指导员工表是那个**

在这个例子中，我们通过 `ChatPromptTemplate` 创建了一个模板，使得 Agent 能够根据用户输入生成相应的数据库查询，并返回查询结果。

​     **RESTful API**（Representational State Transfer）是一种基于HTTP协议的API设计风格，广泛应用于Web服务的集成。通过RESTful API，客户端可以通过HTTP请求与服务器进行交互，获取数据或提交数据。

## 7 Agent 多轮对话的设计

**多轮对话的核心问题**

- **上下文一致性**
  系统需要记住用户之前说过的话，例如用户问“我昨天查的天气是？”时，要能回忆昨天的查询。
- **状态管理**
  在对话中，用户的意图、话题、历史输入都属于“状态”。Agent要有机制来存储、更新和清理这些状态。
- **会话控制**
  - 新对话时清空上下文
  - 长对话中避免“遗忘”关键信息
  - 提供会话ID来区分不同用户/对话

```python
from typing import List, Dict
from langchain_core.chat_history import BaseChatMessageHistory
from langchain_core.messages import BaseMessage


# 自己实现一个最简单的内存消息历史
class InMemoryHistory(BaseChatMessageHistory):
    def __init__(self):
        self._messages: List[BaseMessage] = []

    @property
    def messages(self) -> List[BaseMessage]:
        return self._messages

    def add_messages(self, messages: List[BaseMessage]) -> None:
        self._messages.extend(messages)

    def clear(self) -> None:
        self._messages = []


# 会话存储器（用 dict 管理多个 session）
_store: Dict[str, InMemoryHistory] = {}

def get_session_history(session_id: str) -> InMemoryHistory:
    if session_id not in _store:
        _store[session_id] = InMemoryHistory()
    return _store[session_id]

```

## 8 计算资源管理优化

### 8.1 内存优化

​    优化内存是个关键问题，尤其在涉及多轮对话时。如果你不加控制，内存会不断增长，导致性能下降。针对 多轮对话 的场景，尤其是当  存储大量对话时，可以采用以下几种优化方案：

1. **限制存储的历史消息数量**

一种常见的做法是限制 **每个会话** 存储的历史消息数量。通常来说，过多的历史信息对当前的对话并没有帮助。可以考虑设置 **最大历史长度**，超出部分丢弃或清除。

**代码示例：限制存储的消息数量**

```python
from typing import List, Dict
from langchain_core.chat_history import BaseChatMessageHistory
from langchain_core.messages import BaseMessage

class InMemoryHistory(BaseChatMessageHistory):
    """限制存储历史消息数"""
    def __init__(self,max_history=5):
        self._messages: List[BaseMessage] = []
        self.max_history = max_history

    @property
    def messages(self) -> List[BaseMessage]:
        return self._messages

    def add_messages(self, messages: List[BaseMessage]) -> None:
        self._messages.extend(messages)
        # 保证历史消息数量不超过 max_history
        if len(self._messages) > self.max_history:
            self._messages = self._messages[-self.max_history:]

    def clear(self) -> None:
        self._messages = []


# 会话存储器（用 dict 管理多个 session）
_store: Dict[str, InMemoryHistory] = {}

def get_session_history(session_id: str) -> InMemoryHistory:
    if session_id not in _store:
        _store[session_id] = InMemoryHistory(max_history=5) # 设置最大历史为 5
    return _store[session_id]

```

**解释：**

- **max_history**：控制最大存储消息的数量，一旦超过这个数量，就会丢弃最早的消息。
- **add_messages**：每次添加消息时，检查历史消息数量是否超过最大值，若超过则清除最旧的消息

下面详细讲解每个部分：

**1. 类 RedisChatHistory：用于将历史消息存储在 Redis 中**

```python
# Redis 配置
redis_client = redis.StrictRedis(host='localhost', port=6379, db=0)
class RedisChatHistory(BaseChatMessageHistory):
    """用 Redis 存储历史"""
    def __init__(self, redis_client, max_history=5, session_id=None):
        self.redis_client = redis_client  # Redis 客户端
        self.session_id = session_id      # 会话 ID
        self.max_history = max_history    # 最大历史消息数量

```

- **redis_client**：这是连接 Redis 数据库的客户端（`StrictRedis`）。它用于操作 Redis 数据库。
- **session_id**：每个会话都有一个唯一的 ID（`session_id`），用来区分不同的用户或会话。在 Redis 中，我们会以 `session_id` 为键，存储对应的消息历史。
- **max_history**：表示最大存储历史消息数量。如果消息数量超过这个值，最早的消息会被丢弃。

**2. messages 属性：从 Redis 获取消息并反序列化**

```python
@property
def messages(self) -> List[BaseMessage]:
    """从 Redis 获取消息并反序列化"""
    history_json = self.redis_client.get(self.session_id)  # 从 Redis 获取历史消息
    if history_json:
        messages_dict = json.loads(history_json)  # 将 JSON 字符串反序列化为字典
        return [self._deserialize_message(msg) for msg in messages_dict]  # 反序列化为消息对象
    return []  # 如果 Redis 中没有历史消息，返回空列表

```

- **反序列化（_deserialize_message）**：将字典转换回消息对象以供使用。
- **self.redis_client.get(self.session_id)**：从 Redis 中根据 `session_id` 获取历史消息的 JSON 字符串。
- **json.loads(history_json)**：将从 Redis 获取的 JSON 字符串转换为字典列表。每个字典代表一条消息。
- **self._deserialize_message(msg)**：通过 `_deserialize_message` 方法将字典反序列化为相应的消息对象（`HumanMessage` 或 `AIMessage`）。

这个属性确保了我们可以从 Redis 中获取并反序列化历史消息，以便后续使用。

**3. add_messages 方法：将新的消息存储到 Redis 中**

```python
def add_messages(self, messages: List[BaseMessage]) -> None:
    """将消息序列化后存储到 Redis"""
    current_history = self.messages  # 获取当前存储的历史消息
    current_history.extend(messages)  # 将新消息添加到历史中
    if len(current_history) > self.max_history:
        current_history = current_history[-self.max_history:]  # 如果超过最大历史数，丢弃最早的消息

    # 序列化消息并存储到 Redis
    serialized_messages = [self._serialize_message(msg) for msg in current_history]
    self.redis_client.set(self.session_id, json.dumps(serialized_messages))  # 存储到 Redis 中

```

- **current_history = self.messages**：获取当前历史消息（通过 `messages` 属性获取，已经是反序列化后的对象）。
- **current_history.extend(messages)**：将新的消息添加到历史中。
- **if len(current_history) > self.max_history:**：如果历史消息数量超过了最大值（`max_history`），则丢弃最早的消息，只保留最新的消息。
- **self._serialize_message(msg)**：将每条消息对象序列化为字典，以便能够存储到 Redis 中。
- **self.redis_client.set(self.session_id, json.dumps(serialized_messages))**：将所有消息序列化为 JSON 字符串后存储到 Redis。



**4. clear 方法：清除历史消息**

```python
def clear(self) -> None:
    """清空 Redis 中的历史记录"""
    self.redis_client.delete(self.session_id)

```

- **self.redis_client.delete(self.session_id)**：从 Redis 中删除对应 `session_id` 的历史消息。

**5. _serialize_message 方法：将消息对象序列化为字典**

```python
def _serialize_message(self, message: BaseMessage) -> dict:
    """将消息对象序列化为字典"""
    return {
        "type": message.__class__.__name__,  # 获取消息类型（HumanMessage 或 AIMessage）
        "content": message.content,  # 获取消息内容
        "metadata": message.metadata if hasattr(message, "metadata") else None,  # 获取消息的元数据
    }
```

- **message.__class__.__name__**：获取消息的类型（`HumanMessage` 或 `AIMessage`）。
- **message.content**：获取消息的实际内容。
- **message.metadata**：如果消息包含额外的元数据（`metadata`），则也将其序列化。如果没有，返回 `None`。

这个方法将消息对象转换为字典，以便能够存储在 Redis 中。



**6. _deserialize_message 方法：将字典反序列化为对应的消息对象**

```python
def _deserialize_message(self, msg_dict: dict) -> BaseMessage:
    """将字典反序列化为对应的消息对象"""
    message_type = msg_dict["type"]
    if message_type == "HumanMessage":
        return HumanMessage(content=msg_dict["content"], metadata=msg_dict["metadata"])
    elif message_type == "AIMessage":
        return AIMessage(content=msg_dict["content"], metadata=msg_dict["metadata"])
    else:
        raise ValueError(f"Unsupported message type: {message_type}")

```

- **序列化（_serialize_message）**：将消息转换为字典以便存储。
- **msg_dict["type"]**：根据字典中的 `type` 字段，决定反序列化成 `HumanMessage` 还是 `AIMessage`。
- **HumanMessage(content=msg_dict["content"], metadata=msg_dict["metadata"])**：创建一个新的 `HumanMessage` 或 `AIMessage` 实例，并用字典中的内容填充它。
- 如果消息类型不支持，会抛出 `ValueError`。

这个方法的作用是将从 Redis 中加载的字典数据转换回 LangChain 消息对象，以便后续使用。



**7. get_session_history 方法：获取 `RedisChatHistory` 实例**

```python

def get_session_history(session_id: str) -> RedisChatHistory:
    return RedisChatHistory(redis_client, session_id=session_id)

```

- **get_session_history**：根据传入的 `session_id` 创建一个 `RedisChatHistory` 实例。
- 该方法将返回一个能够与 Redis 交互的历史存储实例，可以通过它获取和存储消息历史。



**总结：**

这个类实现了将历史消息存储到 Redis 中的功能，并且提供了消息的序列化和反序列化机制。通过这种方式，历史消息能够跨会话持久化存储，且在加载时能够恢复成正确的消息类型。

- **序列化（_serialize_message）**：将消息转换为字典以便存储。
- **反序列化（_deserialize_message）**：将字典转换回消息对象以供使用。
- **Redis 存储**：通过 Redis 存储和加载消息历史，可以有效地减少内存占用，且能够跨会话保持消息记录。

这个设计确保了消息历史能够持久化存储，并且可以在不同的会话中共享和恢复历史消息。

### 8.2  缓存优化

**缓存优化**：缓存查询结果来避免重复计算，从而提升响应速度

​       采用 **Redis** 作为缓存会是一个非常好的选择，特别是当应用涉及到频繁的读写操作时。Redis 是一个高性能的内存数据存储系统，适合用来缓存大量数据，极大地提高系统的响应速度

**为什么选择 Redis 作为缓存？**

1. **高性能**：
   - Redis 在内存中存储数据，因此具有极低的延迟。
   - 可以处理大量的请求和高并发操作，适用于需要快速读写数据的场景。
2. **持久化和备份**：
   - Redis 不仅支持内存缓存，还可以将数据持久化到硬盘上，确保数据的可靠性。
   - 适用于需要在缓存失效时恢复数据的场景。
3. **分布式缓存**：
   - Redis 可以作为分布式缓存系统，支持数据的分布式存储，提高系统的可扩展性。
4. **过期时间控制**：
   - Redis 支持设置数据的过期时间，可以避免缓存数据无限增长，减少内存占用。

```python
def get_cached_query_result(query):
    # 使用哈希值作为缓存的唯一键
    redis_key = hashlib.sha256(query.encode()).hexdigest()

    # 尝试从 Redis 中获取缓存数据
    cached_result = redis_client.get(redis_key)
    # 如果缓存数据存在，则返回缓存数据
    if cached_result:
        print("从 Redis 缓存中读取数据")
        return cached_result.decode("utf-8")

    # 如果缓存中没有数据，执行查询并缓存结果
    print("执行大模型推理查询")
    # 执行查询
    result = query_llm(query)
    # 将结果缓存到 Redis 中
    redis_client.set(redis_key, result, ex=60)  # 设置 1 分钟过期时间
```

```python
from mysql.connector import pooling
class SqlArgs(BaseModel):

connection_pool = pooling.MySQLConnectionPool(

      执行SQL查询

        cursor = connection.cursor()
        cursor.execute(query)
        result = cursor.fetchall()
        connection.close()
        return str(result)  # 返回查询结果
    except Exception as e:
        return f"查询失败: {e}"
```

**Neo4j 连接池配置**

```python
from langchain.tools import tool
from pydantic import BaseModel, Field
import os
from dotenv import load_dotenv
from neo4j import GraphDatabase
from neo4j.exceptions import ServiceUnavailable

# 环境变量加载
load_dotenv()


# 连接池管理器
class Neo4jConnectionPool:
    """一个Neo4j连接池管理器"""

    def __init__(self, uri, user, password, max_connections=50):
        # 创建连接池配置
        self.uri = uri
        self.user = user
        self.password = password
        self.max_connections = max_connections
        self.driver = None

    def get_driver(self):
        """获取Neo4j连接驱动，如果没有创建则初始化"""
        if not self.driver:
            self.driver = GraphDatabase.driver(
                self.uri,
                auth=(self.user, self.password),
                max_connection_pool_size=self.max_connections
            )
        return self.driver

    def close(self):
        """关闭连接池"""
        if self.driver:
            self.driver.close()

# 全局连接池
graph_connection_pool = Neo4jConnectionPool(
    uri=os.getenv("NEO4J_URI"),
    user=os.getenv("NEO4J_USERNAME"),
    password=os.getenv("NEO4J_PASSWORD")
)
# Neo4j 查询工具
class Neo4jArgs(BaseModel):
    query: str = Field(description="cypher语句")

@tool(args_schema=Neo4jArgs)
def neo4j_tool(query: str) -> str:
    """
    执行cypher语句查询Neo4j数据库，使用连接池复用连接
    """
    driver = graph_connection_pool.get_driver()
    try:
        with driver.session() as session:
            result = session.run(query)
            # 返回查询结果的字符串表示
            return str([record for record in result])
    except ServiceUnavailable as e:
        return f"Neo4j 异常 : {e}"
```

**关键点说明**

1. **全局连接池**：
   - 我们创建了一个 `Neo4jConnectionPool` 类，在程序启动时就初始化了连接池 (`graph_connection_pool`)，它将复用数据库连接。每次查询都会获取已经建立的连接，而不是每次创建新的连接。
2. **get_driver**：获取连接池中的 `driver`。如果连接池为空，会创建并缓存它。这样可以确保数据库连接在整个应用生命周期内复用。
3. **连接池关闭**：`close` 方法可以在应用退出时手动关闭连接池，释放资源。如果没有特殊需求，Neo4j 会自动管理连接的释放，但我们仍然可以显式关闭连接池。

**优势**

- **性能提升**：避免了每次查询都创建新的连接。连接池会复用已有的连接，大大降低了连接的开销。
- **资源节省**：每个连接的创建和销毁都需要消耗系统资源，连接池通过复用减少了资源的浪费。
- **高并发支持**：通过设置连接池的最大连接数 (`max_connection_pool_size`)，可以支持更多的并发请求。



## 9 项目案例

###  **1 项目描述：**

该项目是一个基于 LangChain 框架的数据库查询系统，结合使用 Redis 缓存、并行计算、多轮对话和大语言模型（LLM）来优化查询性能，并实现更智能的查询交互。系统支持同时查询 SQL 和 Neo4j 数据库，通过多个工具池来处理不同类型的数据库查询，确保高效和准确的查询结果。

**主要功能**：

1. **模型初始化与查询**：
   - 通过 `ChatModel` 初始化大型语言模型（LLM），并结合 `langchain` 提供的工具池来处理数据库查询请求。
   - 模型不仅支持查询 SQL 数据库（`sql_tool_pool`），还支持查询 Neo4j 图数据库（`neo4j_tool_pool`）。
2. **Redis 缓存机制**：
   - 系统使用 Redis 来缓存查询结果，避免重复查询数据库，从而减少数据库访问压力并提高响应速度。
   - 查询结果使用哈希值作为缓存键，并设置 1 分钟的过期时间。这样可以保证查询结果的有效性，同时避免缓存数据过期。
3. **多轮对话支持**：
   - 通过 `RunnableWithMessageHistory` 实现了多轮对话功能，支持查询历史管理，使得每一次查询都能根据前一次的对话状态进行优化。
   - 结合 Redis 存储和获取历史消息，确保会话的连续性。
4. **并行查询优化**：
   - 采用 `ThreadPoolExecutor` 来并行处理多个查询任务，使得多个查询可以在不同线程中并行执行，显著降低了响应时间。
   - `executor.map` 用于并行地执行查询任务，从而提升查询系统的吞吐量。
5. **工具池支持**：
   - 系统同时支持两种数据库工具：`sql_tool_pool` 用于执行 SQL 查询，`neo4j_tool_pool` 用于执行 Neo4j 图数据库查询。每个查询根据需要选择相应的工具池进行处理。

**工作流程：**

1. **初始化**：系统在初始化时加载语言模型（LLM），并配置 Redis 用于缓存查询结果。
2. **查询流程**：
   - 用户输入查询请求，系统根据用户的输入，选择相应的工具（SQL 或 Neo4j）。
   - 首先检查 Redis 中是否已有缓存结果，如果有，则直接返回缓存数据；如果没有，则使用 LLM 进行查询并将结果存入 Redis。
3. **并行处理**：多个查询任务通过线程池并行执行，提高系统的吞吐量和响应速度。
4. **多轮对话管理**：每次查询都可以依赖之前的对话历史，从而实现更智能的对话体验。

**技术栈**：

- **LangChain**：用于构建与数据库的交互流程，支持多轮对话和工具调用。
- **Redis**：用作缓存存储，减少重复查询，优化查询响应速度。
- **Neo4j**：图数据库，用于存储和查询节点数据（如医生节点）。
- **SQL**：关系型数据库，用于存储员工等数据。
- **Python 并行化**：使用 `ThreadPoolExecutor` 进行并行查询优化。

**优点：**

1. **提高查询速度**：通过 Redis 缓存机制和并行查询，显著提高了多次查询的响应速度。
2. **减少数据库负载**：缓存机制避免了对数据库的频繁访问，减轻了数据库的负担。
3. **支持多轮对话**：可以处理多轮对话中的上下文，使查询更加智能和个性化。
4. **扩展性强**：可以根据需求扩展不同的数据库查询工具和功能，如支持更多类型的数据库（SQL、Neo4j 等）。

**优化目标**：

- **性能提升**：通过并行化处理和缓存机制，确保高效、低延迟的查询体验。
- **系统稳定性**：通过 Redis 存储历史和缓存数据，避免系统内存的过度占用，保持系统的稳定运行。
- **智能查询**：通过多轮对话和上下文管理，提升系统的智能化和用户体验。

**示例应用场景**：

1. **企业数据库查询**：用户可以通过自然语言查询企业员工的信息，系统自动解析查询并从数据库中获取相关信息，支持 SQL 和图数据库两种查询方式。
2. **医学数据查询**：用户查询与医生相关的信息（如医生姓名、专长等），系统通过图数据库（Neo4j）处理图形数据，返回高效的查询结果。

**总结**：

该项目展示了如何结合大语言模型、Redis 缓存、多轮对话和并行计算等技术来优化数据库查询的性能，提供一个高效且智能的查询系统，特别适合需要高并发查询和历史上下文管理的应用场景。

```python
import hashlib
import time
import redis
from langchain.agents import create_tool_calling_agent, AgentExecutor
from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder
from langchain_core.runnables import RunnableWithMessageHistory

from model.my_chat_model import ChatModel
from concurrent.futures import ThreadPoolExecutor

from tool.cypher_tool_pool import neo4j_tool_pool
os.environ['LANGCHAIN_VERBOSE'] = 'False'


class LLMProcessor:
    def __init__(self):
        # 在初始化时只创建一次模型
        print("初始化模型...")
        self.model = ChatModel()
        self.llm = self.model.get_line_model()
        # 连接到本地 Redis 服务器
        self.redis_client = redis.StrictRedis(host='localhost', port=6379, db=0)
        print("模型初始化完成")
    # 使用已初始化的模型，完成查询
    def query_llm(self, query):

        prompt = ChatPromptTemplate.from_messages([
            ("system", """
                       你是一个数据库助手，你有两个工具：
                       1 sql_tool_pool 做sql查询
                       2 neo4j_tool_pool 做neo4j查询
                       mysql 数据库表格结构： 
                           employer 员工表
                            表的字段有:user_id 用户id,user_name 姓名,email 邮箱，department 部门
                       neo4j 数据库模式：
                           节点：
                            Doctor 医生节点
                       """),
            ("user", "{input}"),
            MessagesPlaceholder(variable_name="agent_scratchpad"),
        ])
        # 创建一个工具池
        tools = [sql_tool_pool,neo4j_tool_pool]
        agent = create_tool_calling_agent(llm=self.llm, tools=tools, prompt=prompt)
        agent_executor = AgentExecutor(agent=agent, tools=tools, verbose=True)

        # 包装成支持多轮会话的
        agent_with_history = RunnableWithMessageHistory(
            agent_executor,
            get_session_history,#内存优化，获取历史消息,采用redis存历史消息
            input_messages_key="input",
            history_messages_key="history",
            output_messages_key="output",
        )

        # 模拟多轮对话
        config = {"configurable": {"session_id": "userA"}}
        rs = agent_with_history.invoke({"input": query}, config=config)
        return rs["output"]
    # 缓存查询结果
    def get_cached_query_result(self, query):
            # 使用哈希值作为缓存的唯一键
            redis_key = hashlib.sha256(query.encode()).hexdigest()

            # 尝试从 Redis 中获取缓存数据
            cached_result = self.redis_client .get(redis_key)
            # 如果缓存数据存在，则返回缓存数据
            if cached_result:
                print("从 Redis 缓存中读取数据")
                return cached_result.decode("utf-8")

            # 如果缓存中没有数据，执行查询并缓存结果
            print("执行大模型推理查询")
            # 执行查询
            result = self.query_llm(query)
            # 将结果缓存到 Redis 中
            self.redis_client .set(redis_key, result, ex=60)  # 设置 1 分钟过期时间
            return result
#  采用并行优化，创建多个线程执行查询
def query_multiple_databases(queries):
    processor = LLMProcessor()  # 只初始化一次
    # 使用线程池执行查询
    with ThreadPoolExecutor() as executor:  # 限制线程数
        # 使用map方法执行查询
        results = list(executor.map(processor.get_cached_query_result, queries))
    # 返回查询结果
    return results
```
