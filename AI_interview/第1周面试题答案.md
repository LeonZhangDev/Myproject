
**W1-Q1 同步函数、线程和async协程有什么区别？**

同步函数按顺序占用当前线程；线程由操作系统调度，适合阻塞I/O但有切换成本；协程在单线程事件循环中主动让出执行权，适合大量I/O并发。CPU密集任务通常考虑多进程、原生扩展或独立计算服务。

**W1-Q2 Python GIL是什么？它是否意味着Python不能并发？**

GIL使同一进程中通常只有一个线程执行Python字节码，但I/O等待时线程仍可并发，多进程也可利用多核。它限制CPU密集型线程并行，不等于Python不能并发。

**W1-Q3 为什么不建议把可变对象作为函数默认参数？**

 Python 的默认参数不是每次调用函数时重新创建的，而是在函数定义的时候就创建好了。list、dict等可变默认值会在多次调用之间共享状态；通常用None作为默认值，并在函数内部创建新对象。

**W1-Q4 浅拷贝与深拷贝有什么区别？什么情况下容易踩坑？**

浅拷贝只复制最外层容器，内部嵌套对象仍共享引用；深拷贝会递归复制。嵌套列表、配置对象或缓存结果被修改时最容易出现“副本影响原对象”的问题。

**W1-Q5 迭代器和生成器是什么关系？生成器有什么优势？**

迭代器实现__iter__和__next__并按需返回元素；生成器是通过yield创建迭代器的简洁方式。它惰性计算、节省内存，适合流式数据，但通常只能顺序消费。

**W1-Q6 Python装饰器的本质是什么？为什么常使用functools.wraps？**

装饰器本质是接收函数并返回新可调用对象的高阶函数，常通过闭包增加日志、权限或重试逻辑。functools.wraps用于保留原函数名称、文档和签名等元数据。

**W1-Q7 上下文管理器解决什么问题？with语句如何保证资源释放？**

上下文管理器把资源获取和释放绑定到with作用域，通过__enter__/__exit__或contextmanager实现。即使中间抛出异常，退出逻辑仍会运行，适合文件、锁、连接和事务。

**W1-Q8 Coroutine、Task和Future分别是什么？**

调用async函数得到Coroutine对象；Task把协程注册到事件循环并开始调度；Future表示一个未来才会完成的结果，Task是Future的高级封装。业务代码通常直接使用协程与Task。

**W1-Q9 事件循环的作用是什么？协程在什么时候让出执行权？**

事件循环负责调度Task、处理定时器和I/O就绪事件。协程执行到尚未完成的await时让出控制权；普通计算或阻塞调用不会自动让出，因此仍会卡住整个循环。

**W1-Q10 在async def中调用阻塞函数会发生什么？应该怎样处理？**

`async def` 并不会自动把里面所有代码变成异步。如果里面直接调用阻塞函数，比如 `time.sleep()`、同步 HTTP 请求或者同步数据库调用，事件循环一样会被卡住。一般优先换成异步库await asyncio.sleep(5)；同步 I/O 可以丢到线程池；CPU 密集任务则考虑进程池或者独立 Worker。

**W1-Q11 asyncio.gather和TaskGroup有什么主要区别？**

gather便于并发等待一组任务并按输入顺序返回结果；TaskGroup提供结构化并发，子任务失败时会取消同组其他任务，并在退出作用域时统一等待和汇总异常。新代码可优先考虑TaskGroup。

**W1-Q12 异步任务如何设置超时和正确处理取消？**

可使用asyncio.timeout或wait_for设置超时。取消会在协程内触发CancelledError；应在finally中释放资源，完成必要清理后继续传播取消，不要无条件吞掉异常。

**W1-Q13 单线程协程为什么仍可能发生竞态条件？Lock和Semaphore分别解决什么问题？**

同一线程中的多个协程可能在await处交错执行，若共享状态的读改写跨越await，仍会产生竞态。Lock保护临界区；Semaphore限制同时进入某类操作的任务数量。

**W1-Q14 CPU密集任务为什么不适合直接放在事件循环中？有哪些处理方式？**

CPU计算长时间不await，会阻塞事件循环并拖慢所有请求。可使用多进程/ProcessPool、原生扩展、后台任务队列或独立计算服务，并通过限流避免计算任务挤占在线请求。

**W1-Q15 FastAPI依赖注入解决了什么问题？**

依赖注入把数据库会话、认证、配置和公共校验从业务路由中分离，便于复用、测试替换和资源清理。FastAPI还能把依赖参数纳入校验、安全和OpenAPI描述。

**W1-Q16 Pydantic校验和数据库约束有什么区别？**

Pydantic在应用入口校验类型、格式和业务组合规则，并返回友好错误；数据库约束是最终数据防线，可阻止绕过应用的非法写入。唯一性、非空等关键规则通常两层都要有。

**W1-Q17 ASGI和WSGI有什么区别？为什么FastAPI通常运行在ASGI服务器上？**

WSGI主要面向同步HTTP请求响应；ASGI是异步接口规范，可处理并发I/O、WebSocket和长连接事件。FastAPI基于ASGI，通常由Uvicorn等ASGI服务器运行。

**W1-Q18 FastAPI路由应该使用def还是async def？**

调用支持await的异步数据库或HTTP客户端时用async def；必须调用阻塞库时可使用普通def，让FastAPI在线程池执行。最危险的是在async def里直接执行长时间阻塞操作。

**W1-Q19 中间件与依赖注入分别适合处理什么逻辑？**

中间件适合request_id、统一耗时、CORS等几乎所有请求都经过的横切逻辑；依赖注入适合路由级认证、数据库会话和可组合校验，并且更容易按接口声明和在测试中替换。

**W1-Q20 FastAPI lifespan适合管理哪些资源？为什么不应在每个请求中重复初始化？**

lifespan适合在应用启动时创建、关闭时释放连接池、Redis客户端、模型或共享HTTP客户端。复用这些昂贵资源可减少每请求初始化开销，并保证关闭过程可控。

**W1-Q21 BackgroundTasks适合做什么？为什么不能把它当作可靠任务队列？**

BackgroundTasks适合响应返回后执行轻量、短时且允许偶尔失败的同进程任务。它缺少持久队列、跨进程协调和可靠重试；邮件批量发送、模型计算等重要任务应使用Celery/RQ等任务系统。

**W1-Q22 为什么要区分请求模型、数据库模型和响应模型？**

请求模型表达客户端允许提交的数据，数据库模型表达持久化结构，响应模型控制对外返回字段。分离可以避免数据库字段泄露、接口与表结构强耦合，并允许不同版本独立演进。

**W1-Q23 SSE和WebSocket分别适合什么场景？**

SSE是服务器到客户端的单向HTTP事件流，浏览器支持自动重连，适合LLM token输出；WebSocket是全双工长连接，适合实时协作、游戏或双向高频消息。单向生成通常优先SSE。

**W1-Q24 为什么AsyncSession不应该在多个并发任务之间共享？**

AsyncSession是可变、有状态的单个事务上下文，多任务共享会让事务和连接状态互相干扰。通常每个请求或并发任务创建独立Session，并明确提交、回滚和关闭。

**W1-Q25 一个Web请求中的SQLAlchemy Session通常应如何创建、提交、回滚和关闭？**

常见做法是通过yield依赖为每个请求创建Session，在业务边界内提交；出现异常时回滚，并在finally或依赖退出阶段关闭。不要把同一个Session保存为跨请求全局对象。

**W1-Q26 flush、commit和rollback分别做什么？**

flush把待执行SQL发送到数据库并可获得主键，但事务尚未提交；commit提交事务，使修改对其他事务可见并持久化；rollback撤销当前未提交事务并恢复Session可用状态。

**W1-Q27 数据库索引为什么能加速查询？索引是否越多越好？**

索引通过额外数据结构减少全表扫描，但会占用存储并增加写入、更新和维护成本。应依据查询条件、排序、选择性和执行计划设计，而不是给每列都加索引。

**W1-Q28 什么是ORM的N+1查询问题？怎样发现和解决？**

N+1指先查一批主记录，再因懒加载为每条记录额外查询关联数据。可通过SQL日志/查询计数发现，并用selectinload、joinedload、显式Join或批量查询解决。

**W1-Q29 Offset分页和游标分页各有什么优缺点？**

Offset分页简单并支持跳页，但深分页扫描成本高，数据并发变化时还可能重复或遗漏；游标分页按稳定唯一排序键继续查询，性能和一致性更好，但不便任意跳页。

**W1-Q30 数据库连接池耗尽通常有哪些原因？如何排查？**

常见原因包括Session未关闭、事务过长、慢查询、外部调用期间占用连接、流量突增或池配置过小。应先检查 池等待时间、活跃连接数、数据库慢查询和请求trace，再修复泄漏或缩短事务。

- **Session 未关闭**：请求执行完了，但数据库会话没有 `close()`，连接一直被占着，这就是典型的**连接泄漏（Connection Leak，连接泄漏）**。
- **事务过长**：`BEGIN` 以后做了很多事情，迟迟不 `COMMIT / ROLLBACK`，连接会一直被这个事务占用。
- **慢查询（Slow Query，慢查询）**：本来 SQL 应该 20ms 执行完，结果因为缺索引、全表扫描等跑了 5 秒，这 5 秒连接都不能还回池。
- **外部调用期间占用连接**：这是很容易踩的坑。例如先开启数据库事务，然后去请求第三方 API
- - **流量突增**：平时只有 10 个并发，突然来了 500 个并发，即使代码没有泄漏，连接池也可能不够。
- **连接池配置过小**：例如应用能处理 200 个并发请求，但数据库连接池只有：pool_size = 5 大量请求就会等连接。

**W1-Q31 缓存与数据库数据不一致时，你会怎样处理？**

先确定业务一致性要求，再选择Cache-Aside、写后失效、版本号或消息同步；另外缓存本身会设置 TTL，避免错误缓存永久存在。如果删除缓存失败，我还需要有重试或者消息补偿。关键数据以数据库为准，必要时用重试或补偿任务修复。

**W1-Q32 Cache-Aside模式的基本读写流程是什么？**

先 Redis。Redis 有，直接返回。Redis 没有，再查数据库。数据库查到以后写回 Redis。写的时候我一般不是“数据库改一次，Redis 也直接改一次”。因为两个系统很难保证完全原子。
更常见的做法是：先更新数据库；成功以后删除缓存。下一次请求自然会查数据库，然后重新写缓存。这样逻辑会简单很多。不过高并发场景下还是可能有竞态，所以如果一致性要求比较高，还可以加版本号、延迟双删或者消息同步。
消息同步:数据库发生变化后，通过消息队列通知其他系统去更新或删除对应数据

**W1-Q33 缓存穿透、缓存击穿和缓存雪崩分别是什么？**

穿透是反复查询不存在的数据，可用参数校验、空值短缓存或布隆过滤器；击穿是热点Key失效瞬间大量回源，可用互斥重建或逻辑过期；雪崩是大量Key同时失效，可打散TTL、限流和降级。

我一般会做三层防护：第一层是参数校验，直接拦截明显非法的请求；第二层可以使用布隆过滤器，提前判断某个 Key 是否可能存在；第三层是数据库查询为空后，把空结果短时间缓存起来，避免同一个不存在的数据反复查询数据库。布隆过滤器存在假阳性，所以它只能作为前置过滤，不能完全替代数据库查询。

**W1-Q34 使用Redis实现分布式锁时需要注意哪些问题？**

至少使用SET key token NX PX原子加锁，为锁设置合理过期时间，并通过比较token后删除来保证只有持有者释放；长任务需续期。分布式锁不能替代数据库唯一约束和业务幂等。

**W1-Q35 Redis的TTL和内存淘汰策略有什么区别？常见数据结构怎样选择？**

TTL决定某个Key何时过期；淘汰策略是在内存达到上限时选择删除哪些Key。String适合计数/幂等键，Hash适合对象字段，Set适合去重，Sorted Set适合排序，Stream适合消息流。

**W1-Q36 单元测试和集成测试有什么区别？本项目各测什么？**

单元测试隔离函数、服务或工具，速度快；集成测试验证API、数据库、Redis等真实协作。项目中应单测校验和业务逻辑，集成测试关键接口、事务与缓存。

**W1-Q37 pytest fixture、mock和FastAPI dependency_overrides分别适合解决什么问题？**

fixture负责准备并清理可复用测试资源；mock替换外部边界并验证交互；dependency_overrides专门替换FastAPI依赖，如认证、数据库或外部服务。不要把所有内部实现都mock掉。

**W1-Q38 涉及数据库的自动化测试怎样保证用例相互隔离？**

可让每个用例运行在事务中并在结束后回滚，或为测试创建临时数据库/Schema；测试数据使用唯一标识并统一清理。还要避免并行用例共享全局Session或固定主键。

**W1-Q39 Docker镜像和容器有什么区别？Dockerfile与Compose分别负责什么？**

镜像是只读的应用模板，容器是镜像的运行实例。Dockerfile描述单个镜像如何构建；Compose描述API、数据库、Redis等多个服务如何配置网络、卷、环境变量和启动关系。

**W1-Q40 一个FastAPI接口突然变慢，你会按什么顺序排查？**

先用指标确认是首字节还是总耗时，再沿request_id/trace拆分路由、外部API、数据库、Redis和模型耗时；检查慢查询、连接池等待、事件循环阻塞、CPU/内存和近期发布。复现后再针对瓶颈修复并压测回归。
