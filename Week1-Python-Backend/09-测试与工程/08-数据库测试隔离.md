# 数据库测试隔离

## 一句话理解

每个测试要有独立数据边界。

## 核心理解

可每用例事务 rollback、临时 DB/schema、唯一数据；不要并发测试共享全局 Session。

## 🧠 完整理解

### 我会先这样理解

数据库测试隔离的目标是任何一个测试写入的数据都不影响另一个测试。常见做法包括每个测试开启事务并 rollback、创建独立 schema/database、使用容器重建。选择时要看测试是否会自己 commit、是否涉及多连接和后台任务。真正重要的是测试可重复、可并行、顺序无关。

### 执行顺序 / 思考顺序

测试开始准备干净 DB → seed 必要数据 → 执行业务写入 → 做断言 → rollback/清理 schema → 下一个测试从确定状态开始。CI 中可以用 PostgreSQL container 提供真实数据库。

### 容易踩的坑

简单外层事务 rollback 在被测代码内部 commit、多连接并发场景可能失效，需要 SAVEPOINT、连接绑定或独立数据库策略。SQLite 也不一定能替代 PostgreSQL 验证所有行为。

### 面试时我会这样说

> 我最在意的是测试不能互相污染。简单 service 测试可以事务回滚；如果代码内部会 commit 或涉及多连接，我会用更强的隔离方式，宁愿起 PostgreSQL 容器，也不靠 SQLite 假装完全一样。

## 最小代码 / 场景

```python
@pytest.fixture
async def db():
    async with TestSession() as s:
        yield s
        await s.rollback()
```


## 🧪 简单例子与返回结果

### 例子

```text
test_create_user 开始 -> 开启事务
测试中 INSERT user
断言通过 -> ROLLBACK
```

### 运行 / 返回结果

```text
测试内能查到新 user；
测试结束 rollback 后，数据库恢复到测试前状态，不污染下一条测试。
```
