# 参数化测试

## 一句话理解

一份测试逻辑覆盖多组输入边界。

## 核心理解

减少重复测试代码。

## 🧠 完整理解

### 我会先这样理解

参数化测试用同一套测试逻辑跑多组输入，特别适合边界值、等价类和多个错误案例。它减少复制粘贴，并能清楚看到哪一组参数失败。参数化不是为了把完全不同的场景硬塞进一个函数，而是用于“行为相同、数据不同”的测试。

### 执行顺序 / 思考顺序

pytest 收集 `@parametrize` → 为每组参数生成独立 test case id → 分别执行同一测试函数 → 每组独立报告 pass/fail。可以结合 ids 给复杂案例命名。

### 容易踩的坑

参数列表太长会让测试难读；不同前置条件、不同断言逻辑的场景应拆成多个测试。不要把 if/else 全塞进一个参数化函数。

### 面试时我会这样说

> 像分页 size=0、1、100、101 这种边界我很喜欢 parametrize，一套断言跑多组数据。但如果每组案例的业务过程都不一样，我宁愿拆开，测试可读性比省几行代码重要。

## 最小代码 / 场景

```python
@pytest.mark.parametrize('x,ok',[(1,True),(0,False)])
```


## 🧪 简单例子与返回结果

### 例子

```python
import pytest

@pytest.mark.parametrize("a,b,result", [
    (1, 2, 3),
    (2, 3, 5),
    (10, 20, 30),
])
def test_add(a, b, result):
    assert a + b == result
```

### 运行 / 返回结果

```text
$ pytest -q
3 passed
```

**怎么理解：** 同一个测试逻辑自动跑三组参数。
