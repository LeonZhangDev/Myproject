# 身份认证与授权

## 一句话理解

认证回答“你是谁”，授权回答“你能做什么”。

## 核心理解

不要把登录成功等同于有权操作所有资源。

## 🧠 完整理解

### 我会先这样理解

认证（Authentication）回答“你是谁”，授权（Authorization）回答“你能做什么”。用户登录校验密码属于认证；确认当前用户能否删除某项目属于授权。两个阶段必须分清：通过认证的用户不代表拥有所有权限。后端通常先建立身份上下文，再基于角色、资源归属或策略做授权。

### 执行顺序 / 思考顺序

请求携带凭证 → 服务端验证 token/session 得到 user identity → 把当前用户注入请求上下文 → endpoint/依赖根据角色和资源关系检查权限 → 允许执行或返回 401/403。

### 容易踩的坑

401 通常表示未正确认证，403 表示身份已知但没有权限。不能只在前端隐藏按钮做授权，后端必须再次检查。

### 面试时我会这样说

> 我会先把两个概念分开：登录成功只是证明“我是张三”，能不能删这个订单还要看“张三有没有这个权限”。所以前端控制只是体验，真正授权一定放后端。

## 最小代码 / 场景

```text
Authentication -> identity
Authorization -> permission
```


## 🧪 简单例子与返回结果

### 例子

```text
用户提交账号密码 -> Authentication（你是谁）
确认 user_id=1 后访问 /admin -> Authorization（你能做什么）
```

### 运行 / 返回结果

```text
密码正确但角色=user：认证成功
访问仅 admin 可用接口：403 Forbidden
```
