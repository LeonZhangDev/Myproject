# 并发与并行

## 一句话理解

并发是多个任务交替推进；并行是同一时刻真正同时执行。

## 核心理解

I/O 密集常需要高并发；CPU 密集更关心多核并行。

## 🧠 完整理解

### 我会先这样理解

并发强调“多个任务在同一时间段内都有进展”，并行强调“同一时刻真的有多个任务同时执行”。单线程事件循环可以做到高并发，但通常不是 CPU 并行；多进程则可以在多核上并行。选型时不要只看名词，要看任务是 I/O 密集还是 CPU 密集。

### 执行顺序 / 思考顺序

I/O 并发常见路径：任务 A 发请求后等待 → 主动让出 → 任务 B 继续 → 哪个 I/O 先就绪就恢复哪个。CPU 并行则通常是把计算拆给多个进程/原生并行内核，让不同核心同时跑。

### 容易踩的坑

“并发高”不等于“吞吐一定高”，如果下游数据库只有 20 个连接，开 5000 个协程只会把等待队列拉长。并发度必须和下游容量一起设计。

### 面试时我会这样说

> 我会先区分并发和并行：asyncio 很擅长让很多 I/O 任务交替推进，但它不是靠一个线程同时算很多 CPU 任务。如果是大量 HTTP 调用我会用 async；如果是纯 Python 重计算，我会考虑多进程或其他计算方案。

## 最小代码 / 场景

```text
并发: A -> B -> A
并行: Core1:A | Core2:B
```


## 🧪 简单例子与返回结果

### 例子

```python
import asyncio

async def job(name):
    print(name, "开始")
    await asyncio.sleep(0.1)
    print(name, "结束")

async def main():
    await asyncio.gather(job("A"), job("B"))

asyncio.run(main())
```

### 运行 / 返回结果

```text
A 开始
B 开始
A 结束
B 结束
```

**怎么理解：** 这里展示的是并发：A 等待 I/O 时，事件循环可以去运行 B。
