# 进程、线程、协程

## 一句话理解

进程隔离强，线程由 OS 调度，协程由事件循环协作调度。

## 核心理解

协程不是线程，也不会因为 async 自动利用多核。

## 🧠 完整理解

### 我会先这样理解

进程拥有独立地址空间，隔离强、创建和通信成本较高；线程共享进程内存，适合阻塞 I/O，但共享状态需要锁；协程是用户态调度的轻量任务，切换成本低，非常适合大量异步 I/O。三者不是谁“高级”谁“落后”，而是成本、隔离和调度方式不同。

### 执行顺序 / 思考顺序

进程由操作系统隔离和调度；线程也由操作系统调度但共享内存；asyncio 协程则运行在事件循环里，通常在遇到 await 时主动让出执行权。实际服务里三者也可以组合，例如 FastAPI 多进程 worker + 每个 worker 内 asyncio。

### 容易踩的坑

协程一旦调用了阻塞函数，仍然会把事件循环线程卡住；线程共享数据则会出现竞态；进程间对象也不能像线程那样直接共享。

### 面试时我会这样说

> 这三个我一般按“隔离和成本”来理解。进程最重但隔离最好，线程共享内存所以方便但要处理锁，协程最轻但前提是调用链真的异步。后端 I/O 服务里我最常见的是多进程 worker 里跑很多协程。

## 最小代码 / 场景

```text
进程: 独立内存
线程: 共享进程内存
协程: 单线程内协作切换
```


## 🧪 简单例子与返回结果

### 例子

```python
import asyncio

async def fetch(i):
    await asyncio.sleep(0.1)
    return f"task-{i}"

async def main():
    print(await asyncio.gather(fetch(1), fetch(2)))

asyncio.run(main())
```

### 运行 / 返回结果

```text
['task-1', 'task-2']
```

**怎么理解：** 协程适合大量 I/O；线程常用于阻塞 I/O；CPU 密集任务通常考虑多进程。
