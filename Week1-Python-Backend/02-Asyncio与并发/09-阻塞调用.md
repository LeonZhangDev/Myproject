# 阻塞调用

## 一句话理解

阻塞调用占住当前线程；放在事件循环线程会拖慢其他协程。

## 核心理解

优先异步库；无法替换的阻塞 I/O 可 `asyncio.to_thread`；CPU 重任务用进程池/独立服务。

## 🧠 完整理解

### 我会先这样理解

阻塞调用会让当前线程停在那里等结果。在普通同步程序里这很常见；但在 asyncio 的事件循环线程里，一个阻塞调用会让同一个 loop 上的所有协程都失去调度机会。处理方式要看库是否有异步版本：优先换 async client；实在只有同步 API 时，可以用 `asyncio.to_thread` 或线程池把阻塞工作移出去。

### 执行顺序 / 思考顺序

async endpoint → 调到同步阻塞函数 → event loop 线程被占住 → 其他 Task 即使 I/O 已就绪也不能恢复。改成 await 异步驱动，或把阻塞函数 offload 到线程后，loop 才能继续调度其他任务。

### 容易踩的坑

`to_thread` 不是 CPU 密集任务的万能加速器，纯 Python 重计算仍然受 GIL 影响；它主要用来避免同步 I/O 卡住事件循环。

### 面试时我会这样说

> 我排查 async 性能问题时会先看有没有“假异步”，比如 `async def` 里面直接 `requests.get()` 或 `time.sleep()`。这种代码表面上是 async，实际上把 event loop 整个堵住了。

## 最小代码 / 场景

```python
# bad
time.sleep(5)
# better async wait
await asyncio.sleep(5)
```


## 🧪 简单例子与返回结果

### 例子

```python
import asyncio, time

async def bad():
    print("A start")
    time.sleep(0.2)       # 阻塞整个事件循环
    print("A end")

async def other():
    print("B run")

async def main():
    await asyncio.gather(bad(), other())

asyncio.run(main())
```

### 运行 / 返回结果

```text
A start
A end
B run
```

**怎么理解：** 因为 time.sleep 是阻塞调用，B 不能在 A 睡眠期间运行。I/O 异步代码里应优先使用 await asyncio.sleep(...) 或线程池包装阻塞库。
