# 异步超时与取消

## 一句话理解

所有外部 I/O 都应有超时边界，取消要正确清理资源。

## 核心理解

取消触发 `CancelledError`；清理放 finally，通常不要吞掉取消。

## 🧠 完整理解

### 我会先这样理解

异步系统里超时不是锦上添花，而是资源边界。没有超时，一个下游请求可能永远占着连接、Task 和上游等待。取消则是协作式的：Task 收到取消后通常在下一个 await 点抛 `CancelledError`，代码应在 finally 中释放资源，并尽量不要无故吞掉取消信号。

### 执行顺序 / 思考顺序

上层设置 timeout → 操作超时 → 框架触发取消 → Task 在可取消点收到 `CancelledError` → finally 做连接/锁等清理 → 异常向上传播或被超时上下文转换。

### 容易踩的坑

不要只在最外层设一个巨大超时。真实服务常需要连接超时、读取超时、整体 deadline 分层控制；吞掉 CancelledError 可能导致客户端早已离开，服务器任务还在偷偷跑。

### 面试时我会这样说

> 我会把 timeout 当成服务稳定性的一部分，不是“怕报错才加”。下游挂住时，没有超时就等于资源可以无限占用。取消发生以后我也会保证 finally 能正常清理，而不是把 CancelledError 直接吃掉。

## 最小代码 / 场景

```python
async with asyncio.timeout(2):
    await remote_call()
```


## 🧪 简单例子与返回结果

### 例子

```python
import asyncio

async def slow():
    await asyncio.sleep(2)

async def main():
    try:
        await asyncio.wait_for(slow(), timeout=0.1)
    except asyncio.TimeoutError:
        print("timeout")

asyncio.run(main())
```

### 运行 / 返回结果

```text
timeout
```
