# 嵌套模型

## 一句话理解

BaseModel 字段可以继续是 BaseModel。

## 核心理解

适合结构化 JSON、复杂响应。

## 🧠 完整理解

### 我会先这样理解

嵌套模型让复杂 JSON 按层次拆成多个小的 BaseModel，例如订单包含用户、地址和 items。这样每一层都有自己的类型与校验规则，错误位置也能精确到 `items.2.price`。它比在一个巨大 dict 里手工访问键更安全，也更利于复用。

### 执行顺序 / 思考顺序

外层模型读取字段 → 遇到子模型类型 → 递归创建并验证子模型 → 子模型失败时把错误路径拼到外层 → 全部成功后得到由多个模型实例组成的对象树。

### 容易踩的坑

嵌套过深会让 API 契约和更新逻辑很复杂；数据库关系模型也不一定要和 API 嵌套结构一模一样。输入输出模型应按接口需求设计。

### 面试时我会这样说

> 我喜欢用嵌套模型把复杂 JSON 拆小，比如 TripPlan 里 days、activities 分层定义。这样哪一层字段错了能准确定位，也比业务代码里到处 `data['x']['y']` 更稳。

## 最小代码 / 场景

```python
class Task(BaseModel):
    owner:User
```


## 🧪 简单例子与返回结果

### 例子

```python
from pydantic import BaseModel

class Address(BaseModel):
    city: str

class User(BaseModel):
    name: str
    address: Address

u = User(name="Leon", address={"city": "Chengdu"})
print(u.address.city)
```

### 运行 / 返回结果

```text
Chengdu
```
