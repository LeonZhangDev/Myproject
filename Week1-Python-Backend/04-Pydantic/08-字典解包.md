# 字典解包

## 一句话理解

`**dict` 展开成关键字参数。

## 核心理解

常与 `model_dump()` 往返使用。

## 🧠 完整理解

### 我会先这样理解

`**mapping` 会把字典键值展开成关键字参数，常见于 `Model(**data)`、`User(**payload)`。理解它的关键是：字典 key 必须能对应目标函数/构造器接受的参数名，重复参数会报错。它本身不是 Pydantic 特性，只是 Python 调用语法，但在后端 DTO 转换里非常常见。

### 执行顺序 / 思考顺序

先计算 dict → `**` 展开为 `key=value` 参数 → Python 做函数参数绑定 → 再进入目标函数/Pydantic 构造与校验。与 `*args` 展开位置参数的思路对应。

### 容易踩的坑

不要把未经筛选的用户 dict 直接 `**` 给敏感对象或 ORM 构造器，否则可能出现 mass assignment；最好先通过允许字段明确的 Pydantic 模型。

### 面试时我会这样说

> 我会把 `**data` 理解成“把字典摊平成关键字参数”。写起来很方便，但工程里我不会把前端原始 JSON 直接解包进 ORM，而是先过 Pydantic，把允许的字段收紧。

## 最小代码 / 场景

```python
data={'title':'A'}
task=TaskCreate(**data)
```


## 🧪 简单例子与返回结果

### 例子

```python
from pydantic import BaseModel

class User(BaseModel):
    id: int
    name: str

data = {"id": 1, "name": "Leon"}
u = User(**data)
print(u)
```

### 运行 / 返回结果

```text
id=1 name='Leon'
```
