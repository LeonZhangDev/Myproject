# FastAPI 路由

## 一句话理解

路由把 HTTP 方法+路径映射到 Python 函数。

## 核心理解

`@app.get` / `@router.post` 本质是装饰器。

## 🧠 完整理解

### 我会先这样理解

路由负责把“HTTP 方法 + URL 路径”映射到具体 endpoint。路径设计应该表达资源和动作边界，例如 `GET /tasks/{id}` 查询，`POST /tasks` 创建。FastAPI 的 APIRouter 还可以按模块集中管理 prefix、tags、依赖和响应信息，避免 main.py 变成一个巨大的接口文件。

### 执行顺序 / 思考顺序

请求方法和 path 到达应用 → router 按注册顺序和规则匹配 → 解析 path 参数 → 找到 endpoint → 再进入依赖和校验。静态路径与动态路径存在冲突时，定义顺序可能影响匹配。

### 容易踩的坑

不要把所有业务动作都塞进 path 名字里，也不要忽略路由冲突，例如 `/users/me` 和 `/users/{user_id}` 的顺序需要留意。

### 面试时我会这样说

> 我会把路由当成 API 的入口契约，不只是“写个装饰器”。我通常按资源拆 APIRouter，把 prefix、tag、鉴权依赖放在路由组层面，这样接口结构和后续维护都更清楚。

## 最小代码 / 场景

```python
@app.get('/tasks/{task_id}')
async def get_task(task_id:int): return {'id':task_id}
```


## 🧪 简单例子与返回结果

### 例子

```python
from fastapi import FastAPI
app = FastAPI()

@app.get("/users/{user_id}")
def get_user(user_id: int):
    return {"user_id": user_id}
```

### 运行 / 返回结果

```text
GET /users/7
200 OK
{"user_id": 7}
```
