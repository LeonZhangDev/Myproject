# FastAPI 中间件

## 一句话理解

中间件包住几乎所有请求，适合全局横切逻辑。

## 核心理解

典型：request_id、统一耗时、日志、CORS。

## 🧠 完整理解

### 我会先这样理解

中间件包在整个请求处理链外层，可以在路由执行前后统一做事情，例如 request-id、访问日志、耗时统计、安全头、CORS。因为它覆盖几乎所有请求，所以特别适合横切逻辑，但也要保持轻量；在中间件里做慢数据库查询或同步网络 I/O 会影响整个服务。

### 执行顺序 / 思考顺序

请求 → middleware 前置逻辑 → `call_next(request)` 把请求交给下一层/路由 → 得到 response → middleware 后置逻辑 → 返回。多个中间件形成嵌套洋葱结构，注册顺序会影响执行顺序。

### 容易踩的坑

中间件不适合承载大量业务逻辑。还要注意流式响应：如果中间件错误地读取/缓存完整 body，可能破坏 streaming 或带来大内存开销。

### 面试时我会这样说

> 我把 middleware 当成“所有请求都要经过的外壳”。像 request-id 和耗时日志放这里很自然，但业务鉴权如果需要复杂依赖，我更愿意放 Depends，避免中间件越来越重。

## 最小代码 / 场景

```python
@app.middleware('http')
async def mw(request, call_next):
    response=await call_next(request); return response
```


## 🧪 简单例子与返回结果

### 例子

```python
from fastapi import FastAPI, Request
app = FastAPI()

@app.middleware("http")
async def add_header(request: Request, call_next):
    response = await call_next(request)
    response.headers["X-App"] = "demo"
    return response

@app.get("/")
def home():
    return {"ok": True}
```

### 运行 / 返回结果

```text
GET /
200 OK
X-App: demo
{"ok":true}
```
