# 响应模型

## 一句话理解

响应模型控制对外返回字段。

## 核心理解

避免直接暴露 ORM 内部字段、密码、审计信息。

## 🧠 完整理解

### 我会先这样理解

`response_model` 是 API 输出边界，它会根据声明的 Pydantic 模型验证、序列化并过滤返回值。它的意义不仅是生成文档，更重要的是避免 ORM 对象或内部字典里多余的 password、internal_status 等字段被意外暴露。输入模型、数据库模型、输出模型分开，是大型项目很常见的边界设计。

### 执行顺序 / 思考顺序

endpoint 返回 Python/ORM 对象 → FastAPI 根据 response_model 做读取与验证 → 只保留模型允许的字段 → 按 JSON 规则序列化 → 返回客户端。返回数据不符合模型时通常代表服务端代码有 bug。

### 容易踩的坑

不要因为“方便”直接把 ORM 模型所有字段原样暴露。响应模型也会有序列化成本，大结果集应配合分页，必要时做性能评估。

### 面试时我会这样说

> 我把 response_model 看成最后一道输出契约。哪怕内部对象有 password 字段，只要响应模型没定义就不会返回。这样比每个接口手工删字段可靠很多，也能保证文档和真实响应一致。

## 最小代码 / 场景

```python
@app.get('/tasks/{id}', response_model=TaskOut)
```


## 🧪 简单例子与返回结果

### 例子

```python
from fastapi import FastAPI
from pydantic import BaseModel

class UserOut(BaseModel):
    id: int
    name: str

app = FastAPI()

@app.get("/user", response_model=UserOut)
def get_user():
    return {"id": 1, "name": "Leon", "password": "secret"}
```

### 运行 / 返回结果

```text
GET /user
200 OK
{"id":1,"name":"Leon"}
```

**怎么理解：** response_model 会按响应模型过滤/校验返回数据，这里 password 不会出现在响应里。
