# 请求参数

## 一句话理解

FastAPI 根据参数位置和类型注解解析 path/query/header/body。

## 核心理解

类型声明同时帮助校验和 OpenAPI。

## 🧠 完整理解

### 我会先这样理解

FastAPI 会根据函数签名和类型注解判断参数来源：路径里出现的名字通常是 Path 参数，简单类型可作为 Query，Pydantic 模型通常作为 JSON Body，Header/Cookie/File 则有专门声明。明确参数来源可以让校验、文档和错误提示自动化，也避免在 endpoint 里手工解析 request。

### 执行顺序 / 思考顺序

路由匹配 → 从 path/query/header/body 等位置取原始字符串或 JSON → 根据类型注解转换和校验 → 校验失败直接生成 422 → 成功后把已经转换好的 Python 值传给 endpoint。

### 容易踩的坑

Optional 只说明“值可以是 None”，是否真的可以不传还要看默认值；Body 和 Query 的推断也不要只靠猜，复杂接口建议显式声明。

### 面试时我会这样说

> 我写 FastAPI 参数时会尽量让函数签名就能看出接口契约。比如分页就是 query，资源 id 是 path，复杂提交用 Pydantic body。这样校验和 OpenAPI 都能自动跟上，不需要自己到处 `request.json()`。

## 最小代码 / 场景

```python
async def get_task(task_id:int, limit:int=10): ...
```


## 🧪 简单例子与返回结果

### 例子

```python
from fastapi import FastAPI
app = FastAPI()

@app.get("/search")
def search(q: str, limit: int = 10):
    return {"q": q, "limit": limit}
```

### 运行 / 返回结果

```text
GET /search?q=python&limit=3
200 OK
{"q":"python","limit":3}
```
