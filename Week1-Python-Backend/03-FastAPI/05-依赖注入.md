# FastAPI 依赖注入

## 一句话理解

把 Session、认证、配置、公共校验从路由拆出去。

## 核心理解

价值：复用、测试替换、资源清理、接口声明清楚。

## 🧠 完整理解

### 我会先这样理解

依赖注入的核心是“endpoint 声明自己需要什么，而不是自己负责怎么创建”。数据库 Session、当前用户、配置、权限检查都可以做成依赖。FastAPI 会递归解析依赖树，并管理 yield 依赖的清理阶段，因此业务函数可以更专注于业务逻辑，也更容易在测试时替换依赖。

### 执行顺序 / 思考顺序

FastAPI 读取 endpoint 签名 → 找到 Depends → 递归解析子依赖 → 生成依赖值 → 注入 endpoint → endpoint 返回后 → 对 yield 依赖执行清理。一个请求内的依赖结果默认还可以缓存复用。

### 容易踩的坑

依赖注入不是把所有函数都塞进 Depends。纯业务服务层通常可以显式调用；适合依赖注入的是请求上下文、资源获取、横切校验这类边界对象。

### 面试时我会这样说

> 我用依赖注入主要解决“资源和上下文怎么进来”的问题，比如 Session、当前用户、配置。endpoint 只声明我要这些东西，创建和释放交给依赖，这样测试时也能很方便地替换成 fake 或 test DB。

## 最小代码 / 场景

```python
async def route(session=Depends(get_session)):
    ...
```


## 🧪 简单例子与返回结果

### 例子

```python
from fastapi import Depends, FastAPI
app = FastAPI()

def get_current_user():
    return "Leon"

@app.get("/me")
def me(user: str = Depends(get_current_user)):
    return {"user": user}
```

### 运行 / 返回结果

```text
GET /me
200 OK
{"user":"Leon"}
```
