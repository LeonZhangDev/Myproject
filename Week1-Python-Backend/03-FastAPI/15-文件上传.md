# 文件上传

## 一句话理解

`UploadFile` 处理 multipart 文件上传。

## 核心理解

要校验类型/大小/文件名；大文件避免一次性全读内存。

## 🧠 完整理解

### 我会先这样理解

FastAPI 文件上传常用 `UploadFile`，它背后基于临时/缓冲文件接口，适合大文件分块读取，避免一次性把整个文件全部读进内存。接口通常使用 multipart/form-data。工程里除了接收文件，还要考虑大小限制、扩展名与 MIME 校验、病毒扫描、存储路径和文件名安全。

### 执行顺序 / 思考顺序

客户端 multipart 上传 → ASGI 解析 multipart → UploadFile 暴露 filename/content_type/file → endpoint 按块 `await file.read(size)` → 写对象存储/磁盘或进一步处理 → finally/框架关闭文件。

### 容易踩的坑

不能只相信客户端传来的 filename 和 content_type；文件名可能目录穿越，MIME 也可以伪造。大文件应避免 `await file.read()` 无参数一次读完。

### 面试时我会这样说

> 文件上传我一般优先用 UploadFile，不直接用 bytes，因为大文件一次读进内存风险太大。然后会补大小限制、真实文件类型检查和安全文件名，真正生产环境通常再落到对象存储。

## 最小代码 / 场景

```python
async def upload(file:UploadFile):
    content=await file.read()
```


## 🧪 简单例子与返回结果

### 例子

```python
from fastapi import FastAPI, UploadFile
app = FastAPI()

@app.post("/upload")
async def upload(file: UploadFile):
    return {"filename": file.filename}
```

### 运行 / 返回结果

```text
上传文件 avatar.png
200 OK
{"filename":"avatar.png"}
```
