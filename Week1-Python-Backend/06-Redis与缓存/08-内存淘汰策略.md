# 内存淘汰策略

## 一句话理解

Redis 达到内存上限时决定淘汰哪些 Key。

## 核心理解

TTL 是时间规则；淘汰是内存压力规则。

## 🧠 完整理解

### 我会先这样理解

当 Redis 达到 maxmemory 后，需要根据配置的 eviction policy 决定哪些 key 被淘汰。常见策略会在所有 key 或带 TTL 的 key 中按 LRU/LFU/随机/TTL 等规则选择，也可以配置 noeviction 直接拒绝写入。选择取决于 Redis 是纯缓存还是同时承载不能丢的数据。

### 执行顺序 / 思考顺序

写入需要新内存 → 检查 maxmemory → 未超限正常写 → 超限时根据 policy 选择候选 key 并淘汰 → 腾出空间后继续；noeviction 则返回错误。

### 容易踩的坑

LRU/LFU 在 Redis 中通常是近似算法，不是维护一个完美全局排序。把 Redis 同时当缓存和关键持久数据存储时，淘汰策略尤其需要谨慎。

### 面试时我会这样说

> 我会先看这个 Redis 实例的角色。如果它就是缓存，allkeys-lfu/lru 往往合理；如果里面混着绝对不能被淘汰的数据，就不能随便设 allkeys 策略，最好从架构上把用途拆开。

## 最小代码 / 场景

```text
TTL: when expire
Eviction: who to remove when memory full
```


## 🧪 简单例子与返回结果

### 例子

```text
maxmemory 已满
策略：allkeys-lru
```

### 运行 / 返回结果

```text
Redis 会从所有 key 中优先淘汰较久未使用的 key，为新写入腾出空间。
```
