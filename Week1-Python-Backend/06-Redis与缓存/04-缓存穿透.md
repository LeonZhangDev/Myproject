# 缓存穿透

## 一句话理解

反复查询不存在数据，缓存永远 miss，压力打到 DB。

## 核心理解

参数校验、空值短缓存、布隆过滤器。

## 🧠 完整理解

### 我会先这样理解

缓存穿透是不断请求“根本不存在的数据”，因为缓存里没有，数据库里也没有，所以每次都 miss 并打到 DB。攻击者甚至可以用随机 id 放大问题。常见防护是参数合法性校验、空值短缓存和 Bloom Filter；空值缓存要设置较短 TTL，避免真实数据后来创建后长期读不到。

### 执行顺序 / 思考顺序

请求不存在 key → Redis miss → DB 查询也 None → 若什么都不做，下次重复整个流程；改进后写 `__NULL__`/特殊空标记 + 短 TTL → 后续请求直接在 Redis 返回不存在。

### 容易踩的坑

空值缓存会占空间，也可能造成“刚创建的数据仍短暂显示不存在”。Bloom Filter 也有假阳性，不能把它理解成绝对准确的存在性数据库。

### 面试时我会这样说

> 我会先区分穿透和击穿：穿透是“查的东西压根不存在”。解决时我最常用参数校验 + 空值短缓存；数据规模特别大、恶意随机 key 多时再考虑 Bloom Filter。

## 最小代码 / 场景

```python
if obj is None: await redis.set(key,'__NULL__',ex=30)
```


## 🧪 简单例子与返回结果

### 例子

```python
def get_user(user_id):
    key = f"user:{user_id}"
    cached = r.get(key)
    if cached == "__NULL__":
        return None

    user = query_database(user_id)
    if user is None:
        r.set(key, "__NULL__", ex=60)
        return None
    return user
```

### 运行 / 返回结果

```text
第一次查询不存在的 user:999：查 DB，写入 __NULL__
第二次查询 user:999：Redis 命中 __NULL__，直接返回 None
DB 不再被重复打。
```
