# 延迟双删与消息同步

## 一句话理解

高并发下可用二次删除、消息或 CDC 修复短暂不一致。

## 核心理解

复杂方案只在一致性要求确实需要时使用。

## 最小代码 / 场景

```text
DB change -> binlog/CDC/event -> consumer -> invalidate cache
```


## 🧪 简单例子与返回结果

### 例子

```text
更新 user:1：
1. DEL user:1
2. UPDATE DB
3. 延迟一小段时间后再次 DEL user:1
```

### 运行 / 返回结果

```text
即使并发读在更新窗口里把旧值写回缓存，第二次 DEL 也会再次清理它。
下一次读取重新从 DB 获取新值。
```
