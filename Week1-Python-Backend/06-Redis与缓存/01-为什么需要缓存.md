# 为什么需要缓存

## 一句话理解

缓存把高频数据放到更快的存储，减少 DB/下游压力。

## 核心理解

缓存不是数据库替代品；核心问题是失效和一致性。

## 🧠 完整理解

### 我会先这样理解

缓存的本质是把“访问频率高、计算或查询成本高、允许一定副本语义”的数据放到更快的介质里，用空间换时间并保护下游数据库/外部服务。Redis 常被用作跨进程共享缓存，因为内存访问快、数据结构丰富、支持 TTL。真正难点不在 `GET/SET`，而在失效、一致性和热点。

### 执行顺序 / 思考顺序

请求先查缓存 → 命中直接返回，避免访问慢下游 → 未命中才查询 DB/计算 → 把结果写缓存 → 后续请求复用。缓存越靠近热点路径，越能降低平均延迟和下游压力。

### 容易踩的坑

不是所有数据都适合缓存。强一致、极低复用率、数据非常大或更新远多于读取的内容可能收益不高。缓存也不能成为唯一事实来源，除非系统专门这样设计。

### 面试时我会这样说

> 我不会把 Redis 理解成“数据库前面加一层就一定快”。我会先看这个数据是不是读多写少、命中率能不能起来、允许多长时间不一致。缓存真正麻烦的是更新和失效，不是 SET 那一行代码。

## 最小代码 / 场景

```text
Client -> Redis -> miss -> Database
```


## 🧪 简单例子与返回结果

### 例子

```text
第一次查询 user:1：Redis miss -> 查数据库 -> 写 Redis
第二次查询 user:1：Redis hit -> 直接返回缓存
```

### 运行 / 返回结果

```text
第一次：DB 查询 1 次
第二次：DB 查询 0 次
热点数据读取路径更短。
```
