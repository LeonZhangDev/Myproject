# 缓存击穿

## 一句话理解

热点 Key 失效瞬间，大量请求同时回源。

## 核心理解

可互斥重建、逻辑过期、热点提前续期。

## 🧠 完整理解

### 我会先这样理解

缓存击穿是某个非常热点的 key 在失效瞬间，大量并发请求同时 miss，然后一起回源数据库。它和穿透不同：数据本身存在，只是热点缓存刚好没了。常见方案是互斥重建、逻辑过期、热点 key 不同失效策略，以及请求合并。

### 执行顺序 / 思考顺序

热点 key 正常时大量请求都 hit → TTL 到期 → 某一瞬间上百请求同时 miss → 若全部查 DB 就形成尖峰；加互斥后只有一个请求负责回源重建，其他等待/读旧值 → 缓存恢复。

### 容易踩的坑

分布式锁如果设计不当会引入新的故障：锁超时、持锁线程崩溃、安全释放、等待超时都要考虑。并不是所有热点都必须用锁，预热和逻辑过期有时更简单。

### 面试时我会这样说

> 击穿我会理解成“一个明星 key 突然没缓存了，所有人一起冲数据库”。所以重点是控制重建并发，比如只让一个请求回源，其他等一下；如果热点特别确定，也可以提前预热或逻辑过期。

## 最小代码 / 场景

```text
HOT KEY expired -> many requests -> DB
```


## 🧪 简单例子与返回结果

### 例子

```text
热点 key product:1 刚好过期
1000 个请求同时到达
```

### 运行 / 返回结果

```text
没有保护：大量请求一起查 DB
加互斥锁/单飞(singleflight)：1 个请求回源重建缓存，其余等待或使用旧值
```
