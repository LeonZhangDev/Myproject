# 异常处理

## 一句话理解

异常把正常路径与失败路径分开。

## 核心理解

`try/except/finally` 负责捕获与清理；FastAPI 再把业务异常映射成 HTTP 响应。

## 🧠 完整理解

### 我会先这样理解

异常处理的目标不是把所有错误都“压住”，而是把可预期错误转换成调用方能理解的结果，同时让真正的程序缺陷继续暴露。`try` 放可能失败的操作，`except` 尽量捕获具体异常，`else` 放只有成功才执行的逻辑，`finally` 放无论成功失败都要做的清理。工程里还要考虑异常分层：底层异常可以转成领域异常，API 层再转 HTTP 状态码。

### 执行顺序 / 思考顺序

执行 try → 没异常则跳过 except 并可进入 else → 有异常则从匹配的 except 开始处理 → 最后无论哪条路径通常都执行 finally。若 except 中重新 `raise`，异常会继续向上层传播。

### 容易踩的坑

最危险的是大面积 `except Exception: pass`，这会让真实 bug 静默消失。另一个坑是把敏感内部错误原样返回给客户端，可能泄露 SQL、路径或堆栈。

### 面试时我会这样说

> 我处理异常时会先分“这个错误是不是业务上预期的”。比如找不到用户可以转 404；数据库连接断了属于系统异常，要记录完整日志并返回统一错误。我的原则是不乱吞异常，也不把底层细节直接扔给前端。

## 最小代码 / 场景

```python
try: int('x')
except ValueError as e: print(e)
finally: print('cleanup')
```


## 🧪 简单例子与返回结果

### 例子

```python
try:
    x = 10 / 0
except ZeroDivisionError:
    print("不能除以 0")
finally:
    print("清理完成")
```

### 运行 / 返回结果

```text
不能除以 0
清理完成
```
