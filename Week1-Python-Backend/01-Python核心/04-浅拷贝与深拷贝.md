# 浅拷贝与深拷贝

## 一句话理解

浅拷贝只复制外层；深拷贝递归复制嵌套对象。

## 核心理解

嵌套列表/配置最容易踩“副本修改影响原对象”的坑。

## 🧠 完整理解

### 我会先这样理解

浅拷贝只复制最外层容器，里面嵌套对象的引用仍然共享；深拷贝会递归复制可复制的子对象。关键不是记 API，而是先判断数据结构里有没有嵌套可变对象，以及你到底希望哪些层独立。深拷贝虽然隔离更彻底，但成本也更高，而且遇到文件句柄、锁、数据库连接这类对象时并不适合盲目复制。

### 执行顺序 / 思考顺序

原对象 → `copy.copy` 创建新外层 → 内层 list/dict 仍指向旧对象；`copy.deepcopy` 会维护 memo 并递归复制，尽量让嵌套对象也独立。修改最外层字段时浅拷贝通常互不影响，修改共享的内层可变对象时就会互相影响。

### 容易踩的坑

不要为了“安全”一律 deepcopy。对象大、引用复杂或带资源句柄时，深拷贝可能慢、失败，甚至语义不对。很多时候显式构造新的 DTO/字典更清楚。

### 面试时我会这样说

> 我判断浅拷贝还是深拷贝，主要看里面有没有嵌套的可变对象。只有一层 list，浅拷贝通常够；如果里面还有 list，而且我希望完全隔离，就要深拷贝。但工程里我也不会无脑 deepcopy，因为成本和语义都更重。

## 最小代码 / 场景

```python
import copy
a=[[1]]; b=copy.copy(a); c=copy.deepcopy(a)
a[0].append(2); print(b,c)
```


## 🧪 简单例子与返回结果

### 例子

```python
import copy

a = [[1, 2], [3, 4]]
b = copy.copy(a)
c = copy.deepcopy(a)

a[0].append(99)
print(b)
print(c)
```

### 运行 / 返回结果

```text
[[1, 2, 99], [3, 4]]
[[1, 2], [3, 4]]
```

**怎么理解：** 浅拷贝只复制最外层容器；深拷贝连嵌套对象也复制。
