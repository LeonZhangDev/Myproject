# 同步函数

## 一句话理解

普通 `def` 函数按当前线程顺序运行。

## 核心理解

同步不是“慢”的同义词，只表示调用者会等函数返回后再继续。

## 🧠 完整理解

### 我会先这样理解

同步函数最核心的特点不是“慢”，而是调用方会一直沿着当前调用栈往下执行，直到这个函数返回或者抛异常，当前线程才会继续做下一件事。它非常适合步骤明确、必须按顺序完成的逻辑，比如纯计算、简单数据转换、事务内的一组数据库操作。真正需要警惕的是：如果同步函数内部做了耗时 I/O，它会把当前线程一起占住。

### 执行顺序 / 思考顺序

调用函数 → 进入函数体 → 一行一行执行 → 遇到阻塞 I/O 时当前线程等待 → 函数 return → 调用方继续。判断要不要改成异步时，我通常先问：这里主要是在算东西，还是主要在等网络、磁盘、数据库。

### 容易踩的坑

不要把“同步”直接等同于“性能差”。短小的同步逻辑往往更简单、更可靠；问题出在高并发场景下大量同步阻塞 I/O 会占满工作线程。

### 面试时我会这样说

> 我一般把同步函数理解成“调用以后我就在这里等它做完”。如果函数只是做一点 CPU 计算或者很快就返回，同步反而最直接；但如果它里面要等外部接口几秒，高并发时线程就会被白白占着，这时我才会考虑 async。

## 最小代码 / 场景

```python
import time
def task(n):
    time.sleep(1)
    return n
print(task('A')); print(task('B'))
```


## 🧪 简单例子与返回结果

### 例子

```python
def add(a, b):
    print("开始计算")
    return a + b

result = add(2, 3)
print(result)
```

### 运行 / 返回结果

```text
开始计算
5
```
