# 上下文管理器

## 一句话理解

把资源获取与释放绑定到一个作用域。

## 核心理解

即使中间抛异常，退出逻辑仍会执行；文件、锁、连接、事务都常用。

## 🧠 完整理解

### 我会先这样理解

上下文管理器解决的是“资源进入和退出必须成对发生”的问题。`__enter__` 负责建立或拿到资源，`__exit__` 负责释放，即使 with 块中间抛异常，退出逻辑仍然会执行。文件、锁、数据库事务、临时目录都非常适合这种模式，因为它把清理动作从“靠开发者记住”变成了语言结构的一部分。

### 执行顺序 / 思考顺序

进入 `with manager as x` → 调用 `manager.__enter__()` → 执行业务块 → 正常结束或发生异常 → 都会调用 `__exit__(exc_type, exc, tb)` → `__exit__` 返回值还可以决定是否吞掉异常。

### 容易踩的坑

不要默认在 `__exit__` 里返回 True；那会把异常吞掉，可能造成“代码失败了但外面完全不知道”。除非你明确就是要处理这个异常。

### 面试时我会这样说

> 我会把上下文管理器理解成“给资源生命周期上保险”。像文件打开后必须 close、锁 acquire 后必须 release，这些如果手写 try/finally 很容易漏；with 就是把这套进入和退出协议标准化。

## 最小代码 / 场景

```python
with open('a.txt','w') as f:
    f.write('ok')
```


## 🧪 简单例子与返回结果

### 例子

```python
class Demo:
    def __enter__(self):
        print("进入")
        return self

    def __exit__(self, exc_type, exc, tb):
        print("退出")

with Demo():
    print("处理中")
```

### 运行 / 返回结果

```text
进入
处理中
退出
```
