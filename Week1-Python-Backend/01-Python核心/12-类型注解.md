# 类型注解

## 一句话理解

类型注解描述参数、返回值和字段的预期类型。

## 核心理解

IDE、静态分析、FastAPI、Pydantic 都会利用它。

## 🧠 完整理解

### 我会先这样理解

类型注解是给人和工具看的静态语义信息，Python 默认不会因为你写了 `x: int` 就在运行时强制检查。它能让 IDE、mypy/pyright、框架和团队成员更早发现接口不一致，也让函数签名本身成为文档。FastAPI/Pydantic 还会利用注解做参数解析、校验和 OpenAPI 生成，因此在后端工程里注解的价值更大。

### 执行顺序 / 思考顺序

写注解 → 静态工具在开发/CI 阶段分析 → Python 运行时通常照常执行 → 某些框架主动读取 `__annotations__` → 再基于这些信息做校验、序列化或依赖注入。

### 容易踩的坑

不要把类型注解当成运行时安全保证。外部输入仍然必须校验；另外 `Any` 用太多会让静态检查失去意义。

### 面试时我会这样说

> 我把类型注解当成“可执行代码旁边的接口契约”。Python 本身不强制，但 IDE 和静态检查能提前帮我抓很多错，FastAPI 还会直接拿它生成参数校验和文档，所以我在后端项目里会尽量把边界类型写清楚。

## 最小代码 / 场景

```python
def get_task(task_id:int)->dict[str,str]:
    return {'id':str(task_id)}
```


## 🧪 简单例子与返回结果

### 例子

```python
def add(a: int, b: int) -> int:
    return a + b

print(add(2, 3))
print(add.__annotations__)
```

### 运行 / 返回结果

```text
5
{'a': <class 'int'>, 'b': <class 'int'>, 'return': <class 'int'>}
```

**怎么理解：** 类型注解主要帮助 IDE、静态检查器和框架理解数据类型；Python 本身不会因此自动禁止错误类型。
