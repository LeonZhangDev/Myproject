# 迭代器

## 一句话理解

迭代器实现迭代协议，每次只给一个元素。

## 核心理解

`for` 循环内部会不断调用 `next()`，直到 `StopIteration`。

## 🧠 完整理解

### 我会先这样理解

迭代器本质上是一个“记住遍历进度”的对象，实现 `__iter__()` 和 `__next__()`。每次 `next()` 只拿一个元素，耗尽后抛 `StopIteration`。它最大的价值是惰性：不需要一次性把所有数据都放进内存，因此特别适合大文件、数据库游标、流式数据。`for` 循环底层就是不断调用迭代协议，只是把 StopIteration 隐藏了。

### 执行顺序 / 思考顺序

可迭代对象 → `iter(obj)` 得到迭代器 → `next()` 取下一个值并推进状态 → 没数据时抛 `StopIteration` → `for` 捕获后结束循环。很多迭代器是一次性的，遍历完不能自动回到开头。

### 容易踩的坑

“可迭代对象”和“迭代器”不是完全一回事。list 可以反复 `iter()` 得到新迭代器；generator 本身通常既是可迭代对象也是迭代器，而且消费后就没了。

### 面试时我会这样说

> 我把迭代器理解成“带游标的数据访问器”。它不是一次把结果全给我，而是我每要一次，它往前走一步。所以大数据场景很省内存，但也要记住它通常是消费型的，遍历完就不能直接再用。

## 最小代码 / 场景

```python
it=iter([10,20]); print(next(it)); print(next(it))
```


## 🧪 简单例子与返回结果

### 例子

```python
nums = iter([10, 20, 30])
print(next(nums))
print(next(nums))
print(next(nums))
```

### 运行 / 返回结果

```text
10
20
30
```
