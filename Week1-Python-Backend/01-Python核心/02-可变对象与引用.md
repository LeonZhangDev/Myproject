# 可变对象与引用

## 一句话理解

变量更像指向对象的名字；多个变量可指向同一个可变对象。

## 核心理解

list/dict/set 可原地修改，所以共享引用时，一个位置修改会影响另一个名字看到的内容。

## 🧠 完整理解

### 我会先这样理解

Python 变量更像“名字绑定到对象”，而不是传统意义上一个盒子里直接装值。list、dict、set 这类对象可以原地修改，所以两个变量只要指向同一个对象，其中一个地方改了内容，另一个地方看到的也会变化；int、str、tuple 这类通常表现为不可变，所谓“修改”其实是重新绑定到新对象。这个模型能解释很多 Python 里看起来奇怪的副作用。

### 执行顺序 / 思考顺序

先创建对象 → 变量名绑定到对象 → 赋值 `b = a` 时通常只是多了一个引用 → 对可变对象执行原地修改 → a、b 都能看到变化；如果重新赋值 `b = [...]`，则只是让 b 改绑到另一个对象。

### 容易踩的坑

最常见误区是把 `b = a` 当成“复制”。它只复制引用；如果需要独立数据，要根据嵌套层级选择浅拷贝或深拷贝。

### 面试时我会这样说

> 我不会把变量理解成盒子，我更倾向于理解成“标签”。`b = a` 相当于两个标签贴在同一个 list 上，所以改 list 两边都能看到；只有真正 copy 以后，才可能得到独立对象。

## 最小代码 / 场景

```python
a=[1,2]; b=a; b.append(3); print(a)  # [1,2,3]
```


## 🧪 简单例子与返回结果

### 例子

```python
a = [1, 2]
b = a
b.append(3)

print(a)
print(a is b)
```

### 运行 / 返回结果

```text
[1, 2, 3]
True
```

**怎么理解：** a 和 b 指向同一个 list，所以通过 b 修改后，a 也能看到变化。
