# 装饰器

## 一句话理解

装饰器接收函数并返回新的可调用对象。

## 核心理解

常用于日志、鉴权、缓存、重试；FastAPI 的 `@app.get()` 也是装饰器使用。

## 🧠 完整理解

### 我会先这样理解

装饰器的本质是“函数接收函数，再返回一个可调用对象”，常见实现依赖高阶函数和闭包。它适合把横切逻辑从业务函数里抽出去，比如日志、鉴权、缓存、重试、耗时统计。理解装饰器最重要的一步是把 `@timer` 展开成 `func = timer(func)`，这样语法糖背后的调用关系就很清楚了。

### 执行顺序 / 思考顺序

模块加载时执行装饰器表达式 → 原函数作为参数传给 decorator → decorator 返回 wrapper → 原函数名重新绑定到 wrapper → 实际调用时先进 wrapper → wrapper 再决定何时、是否、以什么参数调用原函数。

### 容易踩的坑

装饰器如果不保留原函数元数据，会让 `__name__`、文档、注解甚至签名看起来变成 wrapper；异步函数还要注意 wrapper 自己也要正确 `async/await`。

### 面试时我会这样说

> 我不会死记 `@xxx`，我会先把它展开成 `f = decorator(f)`。这样就知道调用 f 时其实先进入外层 wrapper，所以日志、权限、重试都能在这里统一做。然后我一般会补 `@wraps`，避免把原函数身份信息弄丢。

## 最小代码 / 场景

```python
def log(fn):
    def wrapper(*a,**kw):
        print('call'); return fn(*a,**kw)
    return wrapper
```


## 🧪 简单例子与返回结果

### 例子

```python
def log_call(func):
    def wrapper(*args, **kwargs):
        print("调用前")
        result = func(*args, **kwargs)
        print("调用后")
        return result
    return wrapper

@log_call
def add(a, b):
    print("执行 add")
    return a + b

print("返回值:", add(2, 3))
```

### 运行 / 返回结果

```text
调用前
执行 add
调用后
返回值: 5
```

**怎么理解：** 可以把它理解成 add = log_call(add)：原函数没有改，但外面多包了一层逻辑。
