# 数据库索引

## 一句话理解

索引用额外数据结构减少扫描范围，但增加写入和存储成本。

## 核心理解

依据 WHERE/JOIN/ORDER BY、选择性和执行计划设计，而不是每列都建。

## 🧠 完整理解

### 我会先这样理解

索引是额外维护的数据结构，用空间和写入成本换更快的查找、排序和连接。B-Tree 索引最常见，适合等值和范围查询。索引不是越多越好：每次 INSERT/UPDATE/DELETE 都要维护索引，而且低选择性字段单独建索引未必有收益。真正的设计要从查询模式出发。

### 执行顺序 / 思考顺序

写入数据时同时维护表和相关索引 → 查询时优化器根据条件、统计信息估算成本 → 选择 index scan、bitmap scan 或 seq scan 等 → 通过索引定位行或直接从覆盖索引获取数据。

### 容易踩的坑

复合索引要考虑列顺序与最左前缀；有索引也不代表一定会走，数据量小、选择性差或成本更高时全表扫描可能更合理。

### 面试时我会这样说

> 我建索引不会从字段名字出发，而是从真实 SQL 出发。先看 WHERE、JOIN、ORDER BY 怎么组合，再设计索引，然后用 EXPLAIN 验证。因为索引会拖慢写入，建多了也不是免费。

## 最小代码 / 场景

```sql
CREATE INDEX idx_tasks_user_created ON tasks(user_id,created_at DESC);
```


## 🧪 简单例子与返回结果

### 例子

```sql
CREATE INDEX idx_tasks_user_id ON tasks(user_id);

SELECT * FROM tasks WHERE user_id = 10;
```

### 运行 / 返回结果

```text
查询结果本身不变；
数据库可以利用 idx_tasks_user_id 更快定位 user_id=10 的记录。
```
