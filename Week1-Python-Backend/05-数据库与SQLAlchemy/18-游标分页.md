# 游标分页

## 一句话理解

按稳定唯一排序键继续查询。

## 核心理解

深分页性能和一致性更好，但不方便任意跳页。

## 🧠 完整理解

### 我会先这样理解

游标分页（keyset pagination）不是告诉数据库“跳过多少行”，而是告诉它“从上次最后一条记录之后继续”。通常利用稳定、有索引的排序键，例如 `(created_at, id)`，因此深分页成本比较稳定，也更适合无限滚动和实时数据流。代价是不能轻易随机跳到第 100 页。

### 执行顺序 / 思考顺序

第一页按 `created_at,id` 排序取 limit → 记录最后一行的排序键作为 cursor → 下一页 WHERE `(created_at,id) < (:last_time,:last_id)` → 利用复合索引继续向后扫描 → 返回下一批。

### 容易踩的坑

游标必须与排序条件严格一致，并处理重复排序值，所以常使用时间 + 唯一 id。cursor 对外最好编码/签名，避免客户端随意篡改内部字段。

### 面试时我会这样说

> 我把 cursor 分页理解成“记住上次走到哪里”，而不是每次从头数到 offset。大数据深分页会稳定很多。比如按 created_at 排，我通常再带 id 做 tie-breaker，保证顺序唯一。

## 最小代码 / 场景

```sql
SELECT * FROM tasks WHERE id<:last_id ORDER BY id DESC LIMIT 20;
```


## 🧪 简单例子与返回结果

### 例子

```sql
SELECT id, title
FROM tasks
WHERE id > 20
ORDER BY id
LIMIT 10;
```

### 运行 / 返回结果

```text
如果上一页最后一个 id=20：
返回 id > 20 的下一批最多 10 条记录。
```
