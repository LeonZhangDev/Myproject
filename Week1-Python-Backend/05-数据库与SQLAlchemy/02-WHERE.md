# WHERE

## 一句话理解

`WHERE` 用条件过滤行。

## 核心理解

WHERE 字段常影响索引设计。

## 🧠 完整理解

### 我会先这样理解

WHERE 决定哪些行进入后续处理，是查询性能里非常关键的一层。过滤条件是否可利用索引，和列上的函数、类型转换、组合条件、选择性都有关系。业务上先把条件写对，再观察执行计划，而不是看到“有索引”就默认一定快。

### 执行顺序 / 思考顺序

FROM 确定数据源 → WHERE 对候选行做过滤 → 过滤后的行再参与 GROUP BY/HAVING/SELECT/ORDER BY 等逻辑阶段。物理执行时优化器可能通过索引提前缩小范围，而不是真的先全表扫描再过滤。

### 容易踩的坑

常见坑是对索引列套函数、隐式类型转换，导致索引难以利用；`NULL` 也不能用 `= NULL` 判断，而要用 `IS NULL`。

### 面试时我会这样说

> 我看 WHERE 不只是看条件写没写对，还会看它是不是能有效缩小数据量、能不能走索引。比如对索引列做函数转换，逻辑上没问题，但可能把性能直接从索引查变成全表扫。

## 最小代码 / 场景

```sql
SELECT * FROM tasks WHERE user_id=10 AND done=false;
```


## 🧪 简单例子与返回结果

### 例子

```sql
SELECT id, name
FROM users
WHERE age >= 18;
```

### 运行 / 返回结果

```text
假设数据为：Leon(25)、Tom(16)
返回：
1 | Leon
```
