# 事务

## 一句话理解

一组数据库操作要么一起成功，要么失败回滚。

## 核心理解

事务边界应尽量短，不要拿着数据库连接等待长时间外部 API。

## 🧠 完整理解

### 我会先这样理解

事务把多条数据库操作组成一个逻辑整体，目标是让业务状态从一个合法状态原子地变到另一个合法状态。ACID 中最常被后端直接感知的是原子性和隔离性：要么整组提交，要么失败回滚；并发事务之间还需要通过隔离级别、锁、MVCC 控制可见性。订单扣库存、转账等都依赖事务边界。

### 执行顺序 / 思考顺序

BEGIN → 在同一事务连接上执行多条 SQL → 读取/写入遵循隔离规则 → 全部成功 COMMIT 使修改持久可见 → 任一步失败 ROLLBACK 恢复事务修改。数据库约束也在事务过程中参与校验。

### 容易踩的坑

事务越长，占用连接和锁越久，冲突概率越高。不要在数据库事务里夹着调用慢外部 API；跨服务事务也不能简单靠一个本地数据库事务解决。

### 面试时我会这样说

> 我会先从业务不变量定事务边界，比如“创建订单和扣库存必须一起成功”。事务不是越大越安全，长事务会持锁、占连接，所以我会尽量把数据库内必须原子的步骤收紧在一起，外部调用放到事务外或用消息方案协调。

## 最小代码 / 场景

```python
async with session.begin():
    ...
```


## 🧪 简单例子与返回结果

### 例子

```sql
BEGIN;
UPDATE accounts SET balance = balance - 100 WHERE id = 1;
UPDATE accounts SET balance = balance + 100 WHERE id = 2;
COMMIT;
```

### 运行 / 返回结果

```text
原余额：A=500，B=200
提交后：A=400，B=300
两步作为一个事务整体成功。
```
